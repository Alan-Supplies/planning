이 강의에서는 쿠버네티스의 큐브 API 서버에 대해 설명합니다.

앞서 큐브 API 서버가 쿠버네티스의 기본 관리 컴포넌트라고 설명했습니다.

큐브 제어 명령을 실행하면 큐브 제어 유틸리티가 실제로 큐브 API 서버에 도달합니다.

큐브 API 서버는 먼저 요청을 인증하고 유효성을 검사합니다.

그런 다음 etcd 클러스터에서 데이터를 검색하고 요청된 정보로 다시 응답합니다.

큐브 제어 명령줄을 대신 사용할 필요는 없습니다.

다음과 같이 포스트 요청을 전송하여 API를 직접 호출할 수도 있습니다.

포드 생성의 예를 살펴보겠습니다.

이렇게 하면 이전과 마찬가지로 요청이 먼저 인증된 다음 유효성이 검사됩니다.

이 경우, API 서버는 노드에 할당하지 않고 파드 오브젝트를 생성합니다.

etcd 서버의 정보를 업데이트합니다.

파드가 생성되었음을 사용자에게 업데이트합니다.

스케줄러는 API 서버를 지속적으로 모니터링하여 노드가 할당되지 않은 새 파드가 있다는 것을 인식합니다.

스케줄러는 새 파드 파트를 배치할 올바른 노드를 식별하고 이를 다시 큐브 API 서버에

전달합니다.

그러면 API 서버가 etcd 클러스터의 정보를 업데이트합니다.

그런 다음 API 서버는 해당 정보를 적절한 워커 노드의 Kubelet에 전달합니다.

그런 다음 Kubelet은 노드에 파드를 생성하고 컨테이너 런타임 엔진에 애플리케이션 이미지를 배포하도록

지시합니다.

완료되면 Kubelet은 상태를 API 서버로 다시 업데이트하고 API 서버는 etcd 클러스터에서

데이터를 다시 업데이트합니다.

변경이 요청될 때마다 비슷한 패턴이 반복됩니다.

클러스터를 변경하기 위해 수행해야 하는 모든 다양한 작업의 중심에는 kube API 서버가

있습니다.

요약하면, kube API 서버는 요청을 인증하고 유효성을 검사하며, etcd 데이터 저장소에서 데이터를 검색하고

업데이트하는 역할을 담당합니다.

사실, kube API 서버는 etcd 데이터 저장소와 직접 상호 작용하는 유일한 구성 요소입니다.

스케줄러, kube, 컨트롤러, 관리자 및 Kubelet과 같은 다른 구성 요소는 API

서버를 사용하여 각 영역에서 클러스터의 업데이트를 수행합니다.

kube 관리 도구를 사용하여 클러스터를 부트스트랩한 경우, 이를 알 필요가 없지만, 어려운 방법으로

설정하는 경우, 큐브 API 서버는 쿠버네티스 릴리즈 페이지에서 바이너리로 사용할 수 있습니다.

다운로드하고 Kubernetes 마스터 노드에서 서비스로 실행되도록 구성하세요.

여기에서 볼 수 있듯이 큐브 API 서버는 많은 매개 변수를 사용하여 실행됩니다.

이 섹션에서는 쿠버네티스 아키텍처의 이러한 개별 구성 요소를 설치하고 구성하는

방법을 살펴봅니다.

지금 당장 모든 옵션을 이해할 필요는 없지만, 지금 몇 가지 옵션을 이해하면 나중에

전체 클러스터와 모든 구성 요소를 처음부터 다시 구성할 때 더 쉬워질 것이라고 생각합니다.

쿠버네티스 아키텍처는 다양한 방식으로 서로 통신하며 서로 작동하는 수많은 구성

요소로 이루어져 있습니다.

따라서 다른 구성 요소가 어디에 있는지 모두 알아야 합니다.

인증, 권한 부여, 암호화, 보안 모드가 다양하기 때문에 선택의

폭이 넓습니다.

강좌의 관련 섹션을 살펴볼 때 이 파일을 불러와서 관련 옵션을 살펴보겠습니다.

지금은 몇 가지 중요한 사항을 살펴보겠습니다.

이들 중 상당수는 서로 다른 구성 요소 간의 연결을 보호하는 데 사용되는 인증서입니다.

이 과정의 뒷부분에서 SSL TLS 인증서 강의를 진행할 때 이러한 인증서에 대해 더 자세히 살펴보겠습니다.

이를 위한 전체 섹션이 있으므로 지금은 제거하겠습니다.

하지만 이 섹션에서 살펴볼 다양한 구성 요소에는 모두 인증서가 연결되어 있다는

점만 기억하세요.

etcd 서버 옵션은 etcd 서버의 위치를 지정하는 곳입니다.

이것이 kube API 서버가 etcd 서버에 연결하는 방식입니다.

그렇다면 기존 클러스터에서 kube API 서버 옵션은 어떻게 볼 수 있을까요?

클러스터를 설정하는 방법에 따라 다릅니다.

kube 관리자 도구로 설정하는 경우, kube 관리자는 마스터 노드의 kube 시스템 네임스페이스에

kube API 서버를 파드로 배포합니다.

kube 관리자가 아닌 설정의 ETCD Kubernetes 매니페스트 폴더에 있는 포드 정의 파일 내에서 옵션을

확인할 수 있습니다.

ETCD 시스템d 시스템 Kube apiserver dot 서비스에서 kube API 서버 서비스를 확인하여 옵션을

살펴볼 수 있습니다.

마스터 노드에서 프로세스를 나열하고 kube API 서버를 검색하면 실행 중인 프로세스와

효과적인 옵션을 확인할 수도 있습니다.

이번 강의는 여기까지입니다.
