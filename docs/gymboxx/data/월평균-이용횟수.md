## 계산 정의

- **이용 1회 = 한국시간 일자 기준 중복 제거한 출입일.** 하루 몇 번 찍든 1회
  ([DB_구조_업그레이드_방안.md:104](../../운동기록/DB_구조_업그레이드_방안.md#L104)의 확정 정의)
- 원천 `access_history` — 출입 1건 = 1행, 약 1,950만 행. `created_at`은 **UTC 저장**이라
  `CONVERT_TZ`로 KST 변환 후 일자를 판정한다
- `type` 실측 6종 중 **`ACCESS`(당일 첫 출석)만** 계수한다
  - `REVISIT`(재방문) · `REENTER`(3시간 내 재입장)는 **방문 횟수로 세지 않는다.** 판정 로직상 이
    둘은 그날 이미 `ACCESS`가 찍힌 뒤에만 발생하고(날이 바뀌면 다시 `ACCESS`), 일자 중복 제거
    기준에서는 방문 수를 늘리지 못한다. 필터에 포함해도 결과가 같아 쿼리에서 뺐다
  - 실패 3종 `MULTIPLE_ACCESS_LIMIT`(하루 입장 제한 초과) · `EXPIRED`(회원권 만료) ·
    `GYM_NOT_MATCHED`(지점 불일치)는 게이트를 통과하지 못한 기록이라 제외
  - 참고로 하루 2회 이상 출입(`REVISIT`+`REENTER`)은 2026-07 성공 출입의 **1.2%**(약 1만 건)뿐이다.
    정의를 "일자"가 아니라 "출입 건수"로 바꿔도 8.83회 → 약 8.94회로 결론은 달라지지 않는다.
    하루 입장 제한(`membership.one_day_access_limit`)이 걸려 있어 같은 날 재입장 자체가 드물다
- 모수 B의 회원권 유효 판정: `membership_order.start_at <= 월말 AND expire_at >= 월초`,
  상태에서 `REFUNDED`·`NOT_STARTED` 제외. `EXPIRED` 상태(145만 행)는 **포함** — 지금 만료됐어도
  해당 월에는 유효했던 회원권이다

## 검증

한 회원(2026-07, 22일 방문)의 원시 기록을 직접 대조했다. `ACCESS` 22건의 KST 일자가 모두 서로
다르고, 같은 날 재시도로 찍힌 `MULTIPLE_ACCESS_LIMIT` 3건이 정확히 제외됐다. 집계 로직이
의도대로 동작한다.

## 한계 — 해석 시 주의

1. **자정을 걸친 이용은 이틀로 세어진다.** 실측 샘플에서 23:5x·00:0x 출입이 다수 관찰됐다. 야간
   이용자가 많으면 KST 자정 경계가 방문일수를 부풀릴 수 있다. 필요하면 기준시를 새벽 5시로 옮겨
   재산출한다
2. **모수 C의 분모는 현재 시점 값 고정**이다. 회원 수가 계속 늘고 있어 과거 월일수록 과소 산출된다.
   C의 월별 상승세(1.37 → 1.94)에는 실제 이용 증가와 분모 왜곡이 섞여 있다
3. **일일권(`ONE_DAY`) 방문은 제외됐다.** 월 1만 건 규모지만 `user_id`가 없어(비회원) 회원별
   집계에서 빠진다
4. 6개월 모두 완결된 달만 썼다. 진행 중인 2026-08은 부분 월이라 제외
