# DW·Airflow 구축 일정 초안 (2026-10-16)

## 목표와 범위

- **1차 완료:** `gymboxx-dev` 합성 데이터의 운동 세션·세트 2개 테이블을 MySQL → DMS CDC → S3/Glue/Athena → BigQuery Raw → dbt Warehouse/Mart로 보내고, EKS Airflow DAG가 이를 정기 실행한다. 목표일 **11/20(금)**.
- **최종 운영 전환:** 운영 데이터 범위, 법무·보안, 비용, 장애 복구 기준을 승인받고 운영 배포와 안정화 관찰을 마친다. **12/11(금)은 모든 선행 관문이 11/27까지 충족될 때 가능한 가장 빠른 후보일**이다. 현시점의 확정 목표일은 아니다.
- 1차 PoC 데이터는 `user_exercise_session_history`, `user_exercise_set_history`만 사용한다. `user`, `gym`, `membership` 및 다른 지표는 범위에 넣지 않는다.
- 현재 확정된 배치 위치는 **공용 EKS의 Airflow 1개 + 분리된 Kubernetes dbt Job 1개**다. AWS 접근은 Pod Identity/IRSA, GCP 인증은 WIF를 사용한다. JSON 서비스 계정 키는 발급하지 않는다.

## 현재 위치 (10/16)

- 확인된 완료: DMS Full Load·CDC 성공(8/24 기록), Bronze Athena 적용과 원천 대조(9/1 사용자 확인), EKS Airflow/dbt Job 위치 결정(ADR).
- 확인할 것: 위 검증 증거의 위치, 현재 DMS·Athena 실행 상태, EKS 배포 권한과 namespace/리소스 여유, GCP WIF 권한, BigQuery Raw 생성 여부. 문서에 기록이 없으므로 완료로 간주하지 않는다.
- [PoC 진행상황](../../project/데이터자산화/PoC-진행상황.md)의 “Airflow 호스팅 미정”은 이후 [Airflow 위치 ADR](../../project/데이터자산화/airflow-클라우드위치-adr.md)에서 EKS로 결정됐다. 구현 체크리스트는 [인프라 스택 구현 이슈](../../project/데이터자산화/인프라-스택-구현-이슈.md)를 따른다.
- 기존 업무의 **gymboxx-lib 6.0.0 소비처 전환(10/20)**과 **migration baseline·CI 관문(10/23)**을 침범하지 않도록 첫 주는 준비·권한 확인에 한정한다.
- [데이터 자산화 원안](../../project/데이터자산화/supplies-data-plan.md#7-1-착수-시점과-진입-조건)의 L3 DW 운영 착수 조건 5개는 아직 충족 여부가 확인되지 않았다. 이 일정의 dev 합성 데이터 2개 테이블 PoC는 그 조건과 분리된 제한 범위다.

## 선행관계와 결정 시한

1. **10/23까지:** 담당자, EKS 배포 권한, WIF·IAM, 기존 DMS/Athena 증거를 확보한다. 하나라도 빠지면 10/26 설치 일정을 재산정한다.
2. **10/30까지:** Airflow와 dbt Job의 실행·인증이 통과해야 Raw 적재 작업을 시작한다. Raw 테이블은 이 시점에 없을 수 있다.
3. **11/6까지:** CDC 이벤트 순서, 삭제 의미, 재실행 경계를 확정한다. 이 기준 없이 fact 지표를 완료 처리하지 않는다.
4. **11/9까지:** PO가 “세트 완료”와 0세트 세션의 분모 포함 여부, 날짜 기준을 결정한다. 미결이면 Mart 일정에 영향이 있다.
5. **11/27까지:** 원안의 L3 진입 조건인 ① Wave 1~6 배포 후 30일 안정화 ② 이벤트 97종 수신 검증 ③ 지표 용어사전 등재 ④ DW·제품분석 도구 선정 ⑤ 이벤트와 DB 조인 경로를 각각 확인한다. 운영 데이터 사용에 필요한 법무·보안·비용 승인도 끝나야 11/30 운영 적재를 시작한다. dev 합성 데이터 PoC 승인은 운영 데이터 승인으로 대체되지 않는다.
