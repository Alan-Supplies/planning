# 열려 있는 세션 확인

## 무엇을 하나

`~/.claude/sessions/*.json` 에서 **pid 가 살아 있는 탭**만 골라, 각 탭의 transcript 를 읽고
진행 상태와 닫기 안전도를 판정한다. 읽기 전용이다 — 아무것도 고치거나 종료하지 않는다.

## 실행

기본은 **현재 폴더**의 열린 탭만 본다.

```bash
python3 "$HOME/.claude/skills/open-sessions/scripts/open_sessions.py"
```

옵션:

| 옵션 | 쓸 때 |
| --- | --- |
| `--all` | 모든 프로젝트의 열린 탭을 본다 |
| `--cwd <경로>` | 다른 폴더를 기준으로 본다 |
| `--no-net` | git/gh 조회를 건너뛴다 (빠름, 미푸시·PR 정보 없음) |
| `--json` | 판정 전 원자료를 JSON 으로 낸다 |

`--all` 은 탭 20개 기준 3~4초 걸린다. git/gh 조회 때문이니 급하면 `--no-net` 을 붙인다.

## 결과를 어떻게 전할까

1. 출력은 **요약하지 말고 그대로** 보여준다. 그룹과 순서가 판정 결과다.
2. 맨 위에 한 줄만 덧붙인다 — `지금 닫지 마라` 그룹이 있으면 그것부터 짚는다.
3. 사용자가 특정 탭을 물으면 그 탭의 `마지막 요청`·`마지막 답`·`남은 것` 을 근거로 답한다.
4. **탭을 대신 닫거나 프로세스를 죽이지 않는다.** 판단 재료만 준다.
5. **`0개` 로 나오면 추측하지 마라.** 그 아래에 사유가 같이 찍힌다 — 다른 폴더인지, 죽은
   프로세스인지, 디렉토리를 못 읽은 건지. 그 줄을 그대로 전하고, 필요하면 `--all` 을 권한다.

## 판정 기준

닫기 등급은 세 가지다.

- **지금 닫지 마라** — 진행 중인 턴이나 응답이 버려진다
  - `작업중` 모델이 응답·도구를 실행하는 중
  - `입력대기` 권한 승인이나 질문에 답을 기다리는 중
  - `도구 중단` 도구를 호출해놓고 결과가 없음
  - `응답 없음` 마지막 요청에 답이 없는 채로 멈춤
  - 2시간 안에 띄운 백그라운드 작업이 남아 있는 경우도 여기로 올라간다
- **닫기 전 확인** — 대화는 안 잃지만 결정이나 뒷정리가 남았다
  - `내 답 대기` 마지막 답이 질문으로 끝남
  - `제안만 남음` 다음 조치를 제안만 하고 적용 안 함
  - `한 턴` 요청 한 번으로 끝나 결과 확인이 안 됨
  - 미푸시 커밋, push 안 한 브랜치, 열린 worktree, 수정 요청 받은 PR 도 여기로 올라간다
- **닫아도 된다** — `일단락` 또는 `빈 탭`

`상태` 는 대화 내용으로, `남은 것` 은 git·gh·백그라운드 기록으로 따로 판정한다. 둘 중 더
보수적인 쪽이 닫기 등급이 된다. 근거는 항상 출력에 같이 나오니, 판정이 미심쩍으면
`마지막 답` 을 읽고 사용자에게 다르게 보인다고 말해준다.

## 한계 — 사용자에게 필요하면 밝힐 것

- 상태 판정은 한국어 어투 휴리스틱이라 틀릴 수 있다. 특히 `일단락` 은 "질문 없이 끝남" 이지
  "일이 끝남" 이 아니다.
- **작업 트리의 미커밋 변경은 보지 않는다.** 한 폴더에 탭이 여러 개면 누구 변경인지 가릴 수
  없어서 일부러 뺐다. 미푸시 커밋도 브랜치 단위라 같은 브랜치를 쓰는 탭끼리는 공유된다.
- `gh` 가 없거나 로그인이 안 돼 있으면 PR 칸은 비거나 `조회 실패` 로 나온다.
- 백그라운드 작업은 띄운 기록만 보고 실제 생존은 확인하지 않는다.
- 살아 있는 탭은 `os.kill(pid, 0)` 으로 가린다. 샌드박스가 켜진 프로젝트에서는 남의 프로세스에
  시그널을 못 보내 `EPERM` 이 나는데, 이건 "없다" 가 아니라 "확인 권한이 없다" 라서 **살아 있는
  것으로 센다.** 그래서 이미 죽은 탭이 잠깐 남아 보일 수 있다 — 반대로 놓치는 것보다 낫다.
