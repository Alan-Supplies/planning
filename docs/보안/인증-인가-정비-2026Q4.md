### 2-2. Datadog SAST — 접근 통제 결함

Datadog Code Security 결과 중 자동 수정이 가능한 유형(약한 난수, ReDoS, 신뢰 경계, 오류 메시지 노출)은 Connor가 9~10월에 PR로 처리했다([TECH-2124](https://linear.app/suppliesfitness/issue/TECH-2124)~[TECH-2127](https://linear.app/suppliesfitness/issue/TECH-2127)). 사람 설계가 필요한 **Potential improper access control**(severity high)은 [TECH-1653](https://linear.app/suppliesfitness/issue/TECH-1653)에 모였고 9/16 이후 Backlog에 멈춰 있다.

| 레포 | 건수 |
| --- | --- |
| gymboxx-app-server | 180 |
| preppers-pos-server | 38 |
| 소계 (TECH-1653 본문 상세) | 218 |
| 그 밖의 서버·람다 25개 레포 | 570 |

app-server 180건의 모듈별 분포(TECH-1653 본문):

| 모듈 | 건수 | 모듈 | 건수 |
| --- | --- | --- | --- |
| user | 37 | presale | 5 |
| pt-subscription | 28 | user-gifticon | 5 |
| pt | 17 | badge · challenge · notification · workout | 각 4 |
| user-exercise | 13 | exercise-recommendation · international-user | 각 3 |
| gym | 12 | auth · game · gift · inbody · machine · s3-handler · survey · talk-plus | 각 2 |
| payment | 10 | exercise · health-vote · app.controller | 각 1 |
| membership | 7 | food | 5 |

Datadog 필터(레포명만 교체): `@status:open @finding_type:static_code_vulnerability @rule.name:"Potential improper access control" @git.repository_url:https://github.com/suppliesfitness/<repo>`

이 유형은 "요청으로 받은 userId·gymId·orderId로 조회·수정할 때 요청자가 그 리소스의 소유자·테넌트인지 검증하지 않는다"는 지적이다. 일괄 치환이 불가능하고 잘못 고치면 기능 회귀가 난다. 그래서 패턴을 먼저 정하고 모듈 단위로 간다.

### 2-3. 운영에서 확인된 즉시 조치 대상

- preppers-kds-serverless `authBillReceiver`: 고정 문자열 하나로 **IAMFullAccess가 붙은 IAM 사용자 키**를 돌려준다. dev·prod 모두 열려 있고 키는 git 이력에 평문으로 있다. [검토 문서](../../preppers/람다정리/kds-serverless-dev-스테이지-제거-검토.md) 「보안」 절.
- 노출된 refresh token 폐기와 재노출 방지. [통제판](../../roadmap/중요이슈결정및계획.md) 보류 항목, [토큰 채널 확인](../slack/토큰-채널-확인.md). TECH-452의 폐기 수단이 없어서 폐기 자체가 안 되는 상태다.
- 10월 운영 CS에서 PIN 문자 미수신이 반복됐다. 수신거부 분기는 [TECH-2842](https://linear.app/suppliesfitness/issue/TECH-2842)로 고쳤지만, PIN 재발송 경로에 시도 제한이 없다는 점은 그대로다.

### 2-4. 왜 묶는가

인가 결함과 토큰·PIN 결함은 같은 공격 경로의 앞뒤다. 토큰을 쉽게 얻고(PIN 대입, 365일 토큰 유출) 얻은 토큰으로 남의 리소스를 건드린다(인가 부재). 둘 중 하나만 고치면 측정이 반쪽이 된다. [Datadog 세미나 메모](../security/datadog-secure-2026-후기.md)의 권고도 코드·공급망 보안을 먼저 하라는 것이다.

### 모듈 적용 순서의 근거

건수가 많은 순서가 아니라 **돈과 개인정보가 걸린 순서**다. user(37)는 PII, pt-subscription(28)·pt(17)·payment(10)·membership(7)은 결제와 회차, user-exercise(13)는 10/22 CS에서 확인된 세션 소유자 검증([TECH-701](https://linear.app/suppliesfitness/issue/TECH-701))과 겹친다. gym(12)은 지점 스코프다.

## 7. 위험과 대응

- 인가 추가로 정상 기능이 막힘: shadow 로그 한 주 뒤 차단, 모듈별 e2e, 운영 403·404 비율 모니터링.
- 오탐이 많아 건수가 안 줄어듦: 수용 처리 기준을 2단계에서 문서화하고 Datadog에서 상태를 바꾼다. 수용 사유는 이슈에 남긴다.
- 토큰 수명 단축으로 대량 재로그인: feature flag로 신규 발급분부터 적용, 기존 토큰은 자연 만료. 공지 시점을 앱 팀과 맞춘다.
- `raspberry` 키 교체 중 라즈베리파이 2대 영수증 전송 중단: 새 키를 env에 넣고 동작 확인 뒤 기존 키 비활성화. 매장 영업시간 밖에 한다.
- Weizen 작업과 중복: 1단계 대조 전에는 app-server 보안 PR을 올리지 않는다.
