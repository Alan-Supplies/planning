# 12. 개인 최고 기록 이력 테이블 신설

> [전체 목차](README.md) · [통합 원문](../DB_구조_업그레이드_방안.md)

정체 구간과 최고 기록 달성 수 산출의 전제가 되는 이력 테이블을 신설하는 작업

## 무엇을 바꾸는가

회원×종목 단위로 최고 기록의 이력을 쌓는 테이블 신설 · 갱신할 때 기존 행을 고치지 않고 행을 추가 부위별 최고 기록은 저장하지 않음 — 부위 강도는 종목에 종속되므로 종목 단위 기록에 부위 매핑을 적용해 파생으로 계산 · 작업 원칙 3에 따름

## 어떻게 바꾸는가

기록 종류를 열거형이 아니라 참조 테이블로 관리하기로 확정(2026-08-21)

1. 기록 종류 참조 테이블 신설 — 종류 코드 · 한글 표기명 · 값의 단위 · 유효 범위 · 적용되는 측정 방식 · 정렬 순서 · 상태

2. 최고 기록 이력 테이블 신설 — 회원 · 종목 · 기록 종류 참조 · 기록 값 · 환산 무게 · 반복 수 · 근거 세트 참조 · 달성 시각 · 근사값 여부

3. 갱신 시 행 추가 · 현재 최고값은 부분 고유 제약 또는 조회 뷰로 구분

4. 근거 세트 참조는 세트 대리키(§10)가 전제 — 자연키 복합 기본키를 참조하면 세트가 재삽입될 때 다른 기록을 가리킴

5. 과거 기록으로 초기 적재 — 기존 세트에서 종목별 최고값을 계산해 1건씩 생성 · 달성 시각은 운동 단위 생성 시각으로 근사하고 근사값임을 표시

## 무엇이 선행이고 무엇이 선행이 아닌가

기록 종류 목록 확정은 선행이 아님 — 확정을 선행 조건에서 빼기 위해 참조 테이블을 택하는 것 · 열거형으로 고정하면 종류 목록이 곧 컬럼 정의가 되므로 목록이 확정되기 전에는 테이블을 만들 수 없음 · 참조 테이블이면 그 선후 관계가 끊어지고 종류 추가가 행 삽입으로 끝남

선행 1 — 기록 값을 담는 모양 · 종류를 다 몰라도 결정 가능

|종류|값의 형태|단위|
|---|---|---|
|최고 중량|숫자 1개|킬로그램|
|최고 반복 수|숫자 1개|회|
|단일 세트 최고 훈련량|숫자 1개|킬로그램·회|
|세션 최고 훈련량|숫자 1개|킬로그램·회|
|최장 지속 시간|숫자 1개|초|

전부 숫자 하나 + 단위 형태 · 따라서 기록 값 (숫자) + 단위 (종류 테이블의 메타) + 근거 세트 참조 + 달성 시각 구조로 두면 종류가 몇 개든 같은 모양에 들어감

선행 2 — 측정 방식 선언(§4) · 어느 종류가 어느 종목에 성립하는지를 규칙으로 담으려면 종목별 측정 방식이 먼저 정해져 있어야 함 · 유산소 종목에 "최고 중량" 기록이 생기는 것을 막는 장치가 여기서 나옴 · 강제 순서 §4 → §12

시작 종류는 실측으로 정함 (세트 기록 301,572행 · 2026-08-21)

|항목|값|비율|
|---|---|---|
|무게가 0보다 큰 세트|288,798행|95.8%|
|횟수가 0보다 큰 세트|301,572행|100%|
|무게 없는 세트(횟수만 종목)|12,774행|4.2%|

최고 중량 · 최고 반복 수 · 단일 세트 최고 훈련량 3종으로 시작 · 지금 있는 기록의 95% 이상에서 기록이 생김

최장 지속 시간은 지금 만들지 않음 — 시간 값이 있는 원천은 루틴 계열 44,230행 중 2,061행(4.7%)뿐이고 세트 테이블에는 시간 컬럼이 아예 없음 · 열거형 이었다면 이 종류를 넣을지를 지금 결정해야 했으나, 참조 테이블이면 시간 수집이 정비된 뒤 행 하나 넣으면 됨

## 무엇이 좋아지는가

정체 구간을 산출할 수 있음 — "몇 주째 최고 기록이 갱신되지 않았나"는 최고 기록의 달성 시점이 있어야 계산됨 · 현재값만 알면 정체 여부를 알 수 없음 최고 기록 달성 수를 목표로 쓸 수 있음 — 주간·월간 리포트의 "이번 달 달성한 최고 기록" 항목과 개인 최고 기록 갱신 목표가 이 테이블에 의존 랭킹 조회가 가벼워짐 — 종목별 순위를 낼 때마다 29만 건의 세트를 스캔하는 대신 회원별 최고값만 읽으면 됨 · 모집단 4.5만 명 규모에서 응답 시간 차이가 큼

오염 기록을 사후에 무효화할 수 있음 — 맨몸 종목에 무게가 들어온 세트처럼 잘못된 기록이 최고 기록을 만든 경우, 근거 세트 참조가 있으면 그 최고 기록만 골라 무효 처리 가능 · 참조가 없으면 전량 재계산이 유일한 방법 기준 변경에 강함 — 추정 최대 중량의 계산식이나 반복 수 상한이 바뀌어도, 근거 세트의 무게·반복 수가 남아 있으므로 이력을 다시 만들 수 있음 측정 방식별로 성립하는 기록 종류를 규칙으로 표현할 수 있음 — 종류 참조 테이블에 "적용되는 측정 방식"을 메타로 두면, 새 종목이 등록될 때 그 종목에 어 떤 최고 기록이 생기는지를 사람이 판단하지 않고 규칙이 결정 · 열거형으로는 이 메타를 붙일 자리가 없음 종류를 늘려도 회원 기록 테이블의 정의를 바꾸지 않음 — 최고 기록 이력은 회원 수에 비례해 계속 커지는 테이블이므로, 종류를 하나 늘릴 때마다 이 테이블 의 열거형을 확장하는 것은 대량 테이블 정의 변경을 반복하는 것

## 주의

- 갱신 방식을 수정으로 하면 목적이 사라짐 — 현재값만 남으면 달성 시점과 정체 기간을 알 수 없음 추정 최대 중량은 파생값이므로 계산식과 함께 기록 — 어떤 규칙으로 만든 값인지 남기지 않으면 규칙 변경 후 과거 값과 비교가 불가능 초기 적재분의 달성 시각은 근사값 · 근사 여부를 구분하는 표시가 필요

- 참조 테이블의 한계 — 값이 종류에 맞는지 DB가 보장하지 못함 · 값 모양을 일반화했으므로 "최고 반복 수" 기록에 무게 값이 들어가도 숫자로는 유효함 · 종류 테이블의 단위 · 유효 범위 를 근거로 서버가 검증해야 하며, 이는 열거형 + 종류별 전용 컬럼만큼 강한 보장은 아님 · "종류를 나중에 늘릴 수 있음"과 "값이 종류에 맞는지 DB가 보장함"을 맞바꾼 선택

- 종류 참조 테이블에도 상태 컬럼 필요 — 잘못 등록된 종류를 물리 삭제하면 그 종류로 쌓인 이력이 고아 행이 됨
