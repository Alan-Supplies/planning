## 13-2. 강제 순서

`4` 측정 방식 선언 `──` 필수 선행 `──→  12` 최고 기록 이력 `(` 종류별 성립 규칙 `) 4` 측정 방식 선언 `──` 선행 `──→        5` 장비 `12` 종 `· 6` 부위 기여도 `10` 세트 대리키 `·` 시각 `──` 필수 선행 `──→  12` 최고 기록 이력 `(` 근거 세트 참조 `)`

### 2026-09-03 기준 정리

위 도식은 2026-08-21 기준이다. 현재 남은 강제 순서는 **`4 → 12` 하나뿐**이다.

|종전 강제 순서|현재 상태|
|---|---|
|`4` 측정 방식 → `12` 최고 기록 (종류별 성립 규칙)|**유효** · 단 근거가 `measure_type` enum 에서 `exercise` 플래그 3종으로 바뀜|
|`10` 세트 대리키·시각 → `12` 최고 기록 (근거 세트 참조)|**소멸** — §10 반영 완료(`id` · `done_at` · `created_at` · `updated_at` 존재)|
|`9` 무게 환산 → `12` (값 정확성)|**소멸** — `weight` 를 kg 고정으로 확정해 환산 컬럼 자체가 불필요해짐 · 파운드 기록이 잘못된 순위로 들어가는 문제가 정책으로 해소됨|
|`4` 측정 방식 → `5` 장비 12종 · `6` 부위 기여도|**유효**(필수 아닌 선행)|

- `4 → 12` 의 내용 — 어느 기록 종류가 어느 종목에 성립하는지를 규칙으로 담으려면 종목별 측정 방식 플래그(`has_weight` · `has_duration` · `has_reps`)가 먼저 정해져 있어야 함 · 없으면 유산소 종목에 최고 중량 기록이 생기는 것을 막을 수 없음

- `12` 가 enum 으로 바뀌면서 **기록 종류 목록 확정이 선행 조건으로 되돌아옴** · 목록은 4종(`MAX_WEIGHT` · `MAX_REPS` · `MAX_SET_VOLUME` · `MAX_DURATION`)으로 확정되었으므로 실제로 막히지 않음

- 종전 강제 순서 1건 소멸 — 성격 태그를 두 테이블로 분리하면서 구조 컬럼과 값 추가를 한 작업에서 동시에 확정하므로, "태그 테이블 구조 → 태그 값 추가" 순서 제약이 없어짐

## 13-3. 착수 전제 — 앱 코드 참조 지점 조사

1번(성격 태그 테이블 분리)은 기존 쿼리가 그대로 동작하지 않는 유일한 항목 · `exercise_function` 을 읽는 앱 코드 지점을 전수 조사한 뒤 착수 · 조사 결 과에 따라 즉시 전환과 조회 뷰 단계 전환 중 하나를 선택

- **2026-09-03 기준 4순위 잔여** — 대리키 이관과 시각 컬럼은 이미 적용됐고 무게 환산은 소멸했으므로, 묶어야 할 세트 테이블 변경이 `rpe` 하나만 남았다. 묶음의 근거였던 "변경 횟수 줄이기"가 약해졌으므로 `rpe` 는 필요해질 때 단독 마이그레이션으로 처리해도 된다.
