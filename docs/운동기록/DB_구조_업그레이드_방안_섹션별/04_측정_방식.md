# 04. 측정 방식 선언 컬럼 신설

> [전체 목차](README.md) · [통합 원문](../DB_구조_업그레이드_방안.md)

세트 값의 의미를 운동 마스터 조인 없이 확정하고 서버 검증의 근거를 만드는 작업

## 무엇을 바꾸는가

`exercise` 테이블에 측정 방식 선언 컬럼 신설(값 3종 — 무게+횟수 / 횟수만 / 시간) · 현재는 단위 컬럼과 무게 보유 여부 컬럼의 조합에서 매번 추론(실측 조합 12종)

## 관련 테이블 구조

`exercise                          ←` 측정 방식 컬럼 신설 `(` 운동 정의 `) id · name · unit · has_weight │ user_exercise_session             ←` 세션 `:` 출입 `1` 건당 `1` 개 `·` 세션 강도 보유 `access_history_id · rpe · started_at · end_at │ user_exercise_session_history     ←` 그 세션에서 수행한 운동 `1` 건 `exercise_id · machine_id · is_done │ user_exercise_set_history         ←` 세트 `1` 개 `set_number · count · weight`

문제의 핵심은 세트 테이블의 `count` 컬럼 · 컬럼 주석이 실제로 "횟수 or 초" 이며, 세트 행만 봐서는 `count=30` 이 30회인지 30초인지 알 수 없어 운동 마 스터까지 조인해 추론해야 함 어떻게 바꾸는가

1. `measure_type enum('WEIGHT_REPS','REPS','DURATION') NOT NULL` 추가

2. 단위 × 무게 보유 여부 조합 12종을 매핑해 일괄 부여

3. 서버 검증을 이 컬럼 조회에서 도출 — 하드코딩 금지

|값|**`count`**의 의미|**`weight`**|서버 검증|
|---|---|---|---|
|무게+횟수|횟수|필수|무게 없으면 요청 거부|
|횟수만|횟수|없어야 함|무게가 오면 요청 거부|
|시간|초|없어야 함|무게가 오면 요청 거부|

## 무엇이 좋아지는가

세트 데이터를 단독으로 해석할 수 있게 됨 — 현재는 세트 값의 의미를 알기 위해 상위 두 테이블을 조인해야 하며, 데이터 웨어하우스 적재 시 이 추론이 파이프라인마다 반복됨

오염 데이터 유입 차단 — 맨몸 풀업에 무게가 들어온 세트가 1,621건 · 유일한 검증이 클라이언트 한 곳이었고 어시스트 머신 중량과 추가 중량이 섞여 총부하와 1회 최대 반복 중량 추정을 오염시킴 · 선언 컬럼에서 규칙을 도출하면 운동 유형이 늘어도 검증이 자동 확장 입력 화면이 데이터로 결정됨 — 무엇을 입력받을지가 컬럼 하나로 정해지므로 클라이언트의 폴백 추론 코드를 삭제할 수 있음 · 현재 그 코드가 밴드·구조물 종목을 오판 계산 가능 범위가 명확해짐 — 총부하와 1회 최대 반복 중량 추정은 무게+횟수 종목에서만 성립 · 지금은 대상 판별이 추론이라 계산이 조용히 잘못된 종목을 포함할 수 있음

## 주의

- 거리 측정은 이번에 제외 — 현재 해당 종목 0건이고 저장 컬럼도 없음 · `count` 에 미터를 넣으면 한 컬럼이 횟수·초·거리 3중 의미가 되어 문제가 커짐 · 트레드밀 거리 기록을 실제로 도입할 때 저장 컬럼과 함께 추가
