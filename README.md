# Planning

회사 업무를 계획대로 진행하고, 반복되는 비효율을 줄이기 위한 업무 계획·실행·지식 저장소다.

좋은 계획을 많이 만드는 것보다 **중요한 일을 놓치지 않고 실제로 끝내는 것**을 우선한다. 계획은 실행할 수 있는 다음 행동으로 좁히고, 일일 기록에서 완료 여부를 확인한다.

## 운영 원칙

1. 중요한 이슈는 한곳에서 관리한다.
2. 하루에 반드시 끝낼 일은 1개만 먼저 정한다.
3. 할 일에는 행동과 완료 조건을 함께 적는다.
4. 막힌 일은 방치하지 않고, 막힘을 해소할 다음 행동을 적는다.
5. 미완료 항목은 그대로 복사하지 않고 재계획·대기·중단 중 하나를 결정한다.
6. 반복되는 문제와 해결법은 `docs/`에 남겨 다음 업무 시간을 줄인다.

## 핵심 문서

| 문서 | 역할 | 유지해야 할 내용 |
| --- | --- | --- |
| [`plan/중요이슈결정및계획.md`](plan/중요이슈결정및계획.md) | 중요 이슈 통제판 | 우선순위, 결정, 완료 조건, 바로 다음 행동 |
| [`plan/장기/`](plan/장기/) | 장기 과제 | 자격증·역량 개발처럼 여러 달 지속할 계획과 학습 기록 |
| [`daily/template.md`](daily/template.md) | 일일 실행 템플릿 | 오늘 반드시 끝낼 1개, 추가 업무, 종료 점검 |
| `daily/YYMMDD.md` | 하루 실행 기록 | 오늘 약속한 일과 실제 결과 |
| `docs/` | 지식과 상세 계획 | 설계, 조사, 실행 절차, 회고에서 재사용할 내용 |

상위 통제판에는 세부 작업을 모두 넣지 않는다. 오늘 행동으로 옮길 수 있을 정도로만 좁히고, 긴 설계나 조사 내용은 `docs/`의 별도 문서로 연결한다.

장기 과제는 `plan/장기/`에서 별도로 관리한다. 일일 업무 우선순위와 경쟁시키지 않고 `daily/YYMMDD.md`에 그날 실행할 10~25분짜리 행동만 연결한다.

## 일일 운영

### 업무 시작 전

1. 중요 이슈 통제판을 확인한다.
2. 오늘 진전시켜야 할 이슈 하나를 고른다.
3. 30분 안에 시작할 수 있는 크기의 행동으로 바꾼다.
4. `daily/YYMMDD.md`의 `오늘 반드시 끝낼 1개`에 완료 조건과 함께 적는다.

추가 업무는 최대 2개까지만 약속한다. 그 밖의 요청은 `새로 들어온 일`에 기록한 뒤 우선순위를 판단한다.

### 업무 중

- 완료하면 결과나 산출물 링크를 남긴다.
- 막히면 기다린다고만 적지 않고 담당자 확인, 권한 요청, 재확인 시각 같은 해소 행동을 적는다.
- 더 중요한 일이 들어오면 기존 약속을 지우지 말고 무엇을 미루었는지 기록한다.

### 업무 종료 전

- 완료: 결과를 기록하고 통제판의 다음 행동을 갱신한다.
- 미완료: 다음 날로 자동 복사하지 말고 `재계획`, `대기`, `중단` 중 하나를 선택한다.
- 같은 일이 이틀 연속 미완료라면 범위를 더 작게 나누거나 우선순위를 다시 결정한다.
- 반복해서 시간을 쓴 문제는 `docs/`에 해결법을 정리한다.

## 완료 조건 작성 예시

나쁜 예:

```text
TECH-145 설계 진행
```

좋은 예:

```text
TECH-145 대상 앱 목록과 앱별 설계 산출물을 확정하고 설계 문서에 체크리스트를 남긴다.
```

“진행”, “확인”, “검토”만으로 끝나는 표현을 피한다. 무엇이 만들어지거나 어떤 상태가 되면 끝인지 확인할 수 있어야 한다.

## 디렉터리

- `daily/`: 일일 실행 기록
- `plan/`: 여러 업무를 가로지르는 중요 이슈와 결정
- `docs/`: 제품·기술 지식, 상세 계획, 실행 절차
- `sprint/`: 스프린트 단위 기록
- `project/`: 범위가 분명한 조사·실험
- `presentation/`: 발표 자료
- `skill/`: 반복 작업을 자동화하는 Codex/Claude Code Skill
