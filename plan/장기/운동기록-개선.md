# 운동기록 개선 장기 플랜

> 상태: 계획 수립 완료 · 착수 대기  
> 현재 우선순위: TECH-396 ArgoCD 운영 배포 경로 단일화  
> 상위 정본: [데이터 자산화 기획안](../../project/데이터자산화/supplies-data-plan.md)

## 1. 목적

운동기록 기능에서 지금도 잘못 쌓이는 데이터를 먼저 차단하고, 세션·운동·세트의 의미와 저장 규칙을 확정한 뒤 기능 개선과 Warehouse의 `fact_workout`이 같은 원천을 믿을 수 있게 한다.

이 문서는 데이터 자산화 기획안의 운동기록 관련 작업을 장기 실행 순서로 재구성한 것이다. 결함의 상세 재현 방법과 개별 DoD는 상위 정본 §12·§13을 따르고 여기서 중복 정의하지 않는다.

## 2. 착수 원칙

ArgoCD 완료는 운동기록 기능의 기술적 의존성이 아니라 담당자의 작업량을 통제하기 위한 착수 게이트다.

- TECH-396의 운영 배포 경로 단일화와 검증이 끝날 때까지 본 계획은 신규 대형 작업으로 착수하지 않는다.
- ArgoCD 종료 시 남은 운영 후속 작업과 지원 부담을 확인한 뒤 운동기록의 실제 착수일을 정한다.
- 보안 또는 데이터 오염이 계속되는 결함은 예외다. 재현 결과와 영향이 확인되면 PO 승인으로 최소 수정만 먼저 배포할 수 있다.
- 운동기록 개선이 본격 착수되면 Warehouse는 설계·검증용 얇은 단면만 병행하고, 두 트랙의 대형 배포를 같은 주에 잡지 않는다.

## 3. 범위

### 포함

- 운동 세션의 생성·재개·종료·자동 마감
- 운동·세트 추가, 교체, 삭제, 순서 보존
- `started_at`, `end_at`, `source`, `access_history_id` 의미 확정
- 무게 원본 단위와 집계용 kg, 횟수와 시간 단위 정합
- 이전 기록 불러오기와 추천·실제 수행 연결
- 외부 운동 기록
- 공통 라이브러리와 기존 테이블 변경
- 운동 기록률·완료율·총 무게·운동 시간의 검증 기준

### 제외

- 전체 Warehouse 구축
- 목표·캘린더·푸시 기능 자체의 신규 개발
- 과거 오염 데이터의 전면 소급 복원
- PT 추천 알고리즘의 품질 개선
- 운동기구 마스터 데이터의 전면 정비

제외 항목이 운동기록과 같은 스키마를 사용할 경우 인터페이스와 배포 순서만 이 계획에서 조정한다.

## 4. 현재 기준선

상위 정본의 2026-07 실측을 시작 기준으로 사용하되, 착수 첫 주에 다시 측정한다.

| 항목 | 확인된 상태 | 의미 |
| --- | --- | --- |
| 기록 보유 세션 | 최근 90일 세션의 8.4% | 기능 사용성과 데이터 완결성이 모두 낮음 |
| 운동 시간 | 평균 약 111분 | `started_at`이 출석 시각을 복사해 지표 왜곡 |
| 미종료 세션 | `end_at IS NULL` 17.8% | 시간·완료율 계산 불가 |
| RPE 결측 | 44.6% | 강제 필수화보다 수집 흐름과 자동 마감 구분이 필요 |
| 허위 세트 | 상세 화면 진입만으로 저장 가능 | 총 세트·총 무게·작성률 오염 |
| 무게 단위 | lb 재진입 시 이중 변환 | 사용자 값 훼손 |
| 총 무게 | 시간 운동까지 `weight × count` 합산 | 요약·완료 화면 간 수치 불일치 |
| 순서 | `round_number` 중복 가능 | 서버 데이터만으로 운동 순서 복원 불가 |

## 5. 목표 데이터 계약

다음 항목은 구현보다 먼저 확정하고 용어사전과 테스트에 같은 문장으로 남긴다.

1. `started_at`
   - GYM과 OUTSIDE 세션별 채우기 시점
   - 미래 시각과 과거 시각 허용 범위
   - 의미 전환 시점과 과거 데이터 처리 방침
2. `source`
   - `GYM`, `OUTSIDE`의 생성 조건
   - `access_history_id`와 `gym_id`의 허용 조합
3. 무게
   - 사용자가 입력한 값과 단위를 원본으로 보존
   - 비교·집계용 kg는 단일 규칙으로 계산
4. 횟수와 시간
   - 운동 단위가 `SET`이면 횟수, `SECOND`이면 초
   - 시간 운동을 총 무게에서 제외
5. 완료와 자동 마감
   - 사용자 완료, 중단, 자동 마감을 지표에서 구분
6. 삭제
   - 화면에서 삭제한 운동이 이전 기록과 집계에서 다시 나타나지 않음

## 6. 단계별 실행

### Gate A. ArgoCD 집중 작업 종료

진입 조건:

- TECH-396의 운영 배포 경로가 ArgoCD 단일 경로로 전환됨
- `platform-root`와 대상 Application의 기대 상태가 검증됨
- 직접 `kubectl apply` 제거 또는 잔존 예외가 문서화됨
- 전환 직후 운영 관찰 기간과 담당자의 지원 부담이 합의됨

종료 산출물:

- 운동기록 착수일
- 담당자별 가용 용량
- 운동기록 배포가 사용할 실제 CI/CD 경로 확인

### Phase 0. 재측정과 결정 고정

작업:

- 상위 정본의 E-1~E-14 재현 여부 재확인
- `started_at`, `source`, 단위, 자동 마감 정의 확정
- 과거 데이터 소급 보정 범위 결정
- 보안 결함 E-10의 현재 재현 여부와 오염 건수 확인
- P0와 P1의 실제 티켓 소유권 중복 제거

종료 조건:

- 핵심 정의에 계산식·제외 조건·검증 쿼리가 있음
- 수정 대상 repo와 배포 순서가 확정됨
- 스키마 변경 전후 롤백 기준이 있음

### Phase 1. 보안과 진행 중인 오염 차단

우선순위:

1. 타인의 `access_history_id`로 세션을 생성할 수 없게 소유자 검증
2. 상세 화면 진입만으로 세트가 저장되는 동작 차단
3. lb 이중 변환 제거
4. 총 무게 산식 통일

종료 조건:

- 각 결함의 재현 테스트가 수정 후 실패함
- 신규 오염 행이 발생하지 않음
- 완료·요약·공유 화면에서 같은 픽스처의 총 무게가 일치함

### Phase 2. 스키마와 공통 라이브러리 정합화

작업:

- `round_number` 중복 데이터 사전 정리
- `user_exercise_session`과 `user_exercise_session_history` 변경 통합
- `access_history_id` nullable, `source`, 템플릿·프로그램 연결 컬럼 반영
- 세션 내 운동 순서를 보장하는 유일성 제약 적용
- gymboxx-lib 릴리스와 소비 repo 영향 확인
- 스테이징에서 DDL 알고리즘·소요시간·락 영향을 먼저 측정

종료 조건:

- 정합화 스크립트가 멱등함
- 스테이징과 운영에서 계획한 DDL이 성공함
- 구버전 소비자가 허용 범위에서 계속 동작함
- 롤백과 기능 플래그 절차가 검증됨

### Phase 3. 세션 생애주기와 기능 완결

작업:

- `started_at` 서버 채우기
- 운동 교체 API 원자화
- 삭제 후 종료가 실제 삭제를 수행하도록 수정
- 이전 기록 조회에서 삭제·미완료·중단 기록 제외
- 이전 기록 조회를 `exercise_id` 없이도 호출할 수 있게 하고 `done_at DESC` 순서를 보장
- 3시간 하드 만료 제거와 12시간 서버 자동 마감
- 외부 운동 세션 생성·조회·종료
- 추천 템플릿과 실제 수행 세션 연결
- 클라이언트 잔여 오류와 중복 헬퍼 정리

종료 조건:

- GYM·OUTSIDE 각각 생성부터 종료까지 E2E 통과
- 교체·삭제·재개 반복 후에도 순서와 값이 보존됨
- 자동 마감이 사용자 완료와 구분됨
- 이전 기록에 삭제·미완료 데이터가 노출되지 않음
- `exercise_id` 유무와 관계없이 이전 기록 조회가 성공하고 결과가 `done_at DESC`로 정렬됨

### Phase 4. 품질 추적과 Warehouse 계약 고정

작업:

- 기록 보유 세션, 운동 시간, 총 무게, 완료율의 주간 추적
- 신규 세션의 `end_at` 결측률 추적
- GYM·OUTSIDE와 사용자 완료·자동 마감 분리 집계
- `fact_workout`이 사용할 그레인과 필드 계약 작성
- 원천과 Warehouse의 대사 쿼리 작성

종료 조건:

- 기록 보유 세션의 개선 목표치가 PO에 의해 확정됨
- 신규 세션 `end_at` 결측률이 목표 범위에 들어옴
- 운영 DB와 Warehouse 샘플 집계가 허용 오차 안에서 일치함
- 지표 정의 변경이 코드 리뷰를 거치도록 소유권이 정해짐

## 7. 배포 원칙

- 스키마 변경, 서버, 배치, 클라이언트의 배포 순서를 하나의 런북으로 관리한다.
- 같은 테이블의 ALTER를 기능별로 중복 실행하지 않는다.
- 데이터 정합화 후 제약을 추가한다.
- 클라이언트 기능은 플래그를 닫은 상태로 먼저 배포한다.
- 자동 마감 배치는 dry-run과 대상 건수 확인 후 활성화한다.
- 운동기록의 대형 DDL과 Warehouse 적재 구조 변경을 같은 배포 창에 두지 않는다.

## 8. 역할 분리

| 책임 | 필요한 결정·작업 |
| --- | --- |
| PO | `started_at`, OUTSIDE, 성공 지표, 과거 데이터 정책 승인 |
| Backend/DB | 소유자 검증, 스키마, API 원자성, 배치, DDL |
| Client | 자동 저장 제거, 단위 표시, 삭제·재개 흐름 |
| QA | GYM·OUTSIDE·kg·lb·시간 운동 조합의 회귀 시나리오 |
| Data | 지표 정의, 추적 쿼리, Warehouse 계약과 대사 |

한 사람이 Backend·DB·Data를 겸할 수는 있지만 PO 결정과 Client 수정까지 대신 소유하는 일정은 수립하지 않는다.

## 9. 성공 기준

- 재현 가능한 보안 결함 0건
- 화면 진입만으로 생성되는 세트 0건
- kg·lb 왕복 저장 후 값 변형 0건
- 시간 운동이 총 무게에 포함되는 사례 0건
- 동일 세션 내 운동 순서 중복 0건
- GYM·OUTSIDE 세션의 생성부터 종료까지 E2E 통과
- 자동 마감과 사용자 완료를 분석에서 구분 가능
- `fact_workout` 구축에 필요한 필드 의미가 문서와 테스트로 고정

정확한 목표 비율은 착수 재측정 후 PO가 확정한다. 기준선이 없는 상태에서 임의의 개선 수치를 약속하지 않는다.

## 10. 주요 미결

- GYM 세션의 `started_at`을 세션 생성과 첫 운동 추가 중 어디로 볼 것인가
- OUTSIDE 세션의 `gym_id` NULL 허용 범위
- 자동 마감을 별도 컬럼으로 식별할 것인가
- 과거 허위 세트와 중복 순서를 어디까지 보정할 것인가
- 2-pass 순서 재부여 로직을 템플릿과 공용화할 것인가
- 기록 보유 세션 8.4%의 개선 목표를 얼마로 잡을 것인가
