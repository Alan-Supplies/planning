## 01 · 지금 당장 (온보딩) — TECH-575 · TECH-576

두 이슈 모두 제목만 있고 설명이 비어 있다. `Habit-OS-1단계-온보딩.md`의 완료조건을 백엔드 관점으로 채워 넣은 실행 체크리스트는 아래와 같다.

### TECH-575 — [Habit] 관련 짐박스 도메인 파악 (In Progress, 2026-08-05 시작)

- [ ] 짐박스 앱 현재 도메인 모델 정리: 회원(user) · 지점(gym) · 출석(attendance) · 운동기록 · 챌린지 · PT 예약/수업
- [ ] `user_exercise_metadata` 등 기존 목표/레벨 테이블 구조 확인 — 이력 없이 최신값을 덮어쓰는 구조, 실측 23,765행 (`TECH-600` 언급)
- [ ] 인바디 관련 기존 테이블(`user_inbody`, `user_inbody_access`, `gym_inbody_machine`, `user_trainer_inbody_share`) 구조와 2024-11-22 이후 적재 중단 상태 확인 (`TECH-603`)
- [ ] 현행 출석 · 운동기록 · 챌린지가 서로 어떤 테이블을 채우고 참조하는지 관계 정리
- [ ] 오염원 3건(자동 저장 · lb 이중 변환 · 총무게 산식)의 실제 발생 지점을 코드/쿼리 수준에서 확인 (`TECH-609` 제약 3 대응)

### TECH-576 — [Habit] 관련 서버 구조 파악 (Todo, 미착수)

- [ ] 짐박스 앱 서버 레포 구조 · 서비스 경계 · 배포 파이프라인 파악
- [ ] 배치/스케줄러 유무 확인 — `TECH-600`은 "앱 서버에 스케줄러가 없어 배치 서버가 유일 선택"이라고 명시. 실제로 쓸 수 있는 배치 서버가 있는지, 신설해야 하는지 확인
- [ ] 웹뷰-앱 계측 조인 가능 여부 확인 — 목표 등록·수정은 웹, 홈 위젯·상세는 네이티브로 나뉘는데 웹뷰 계측이 앱과 분리되어 있음 (`TECH-600` 제약 5)
- [ ] Firebase/Braze/Clarity 등 계측 인프라 접근 권한과 현재 이벤트 택소노미 존재 여부 확인 (온보딩 문서 완료조건)

## 02 · Wave 1 백엔드 로드맵 (기능 순서: 1-1 → 1-2 → 1-3 → 1-4 → 1-5 → 1-6)

| 기능 | Linear 상태 | 백엔드가 할 일 |
|---|---|---|
| 1-1 운동 기록 + 실시간 제안 | `TECH-609` 기획 In Progress (Harvey). 서브이슈 `TECH-562`(진입점, 류지예) · `TECH-563`(과거기록 수정 flow, 류지예)는 전부 FE/디자인 — 백엔드 서브이슈 미생성 | 아래 상세 참고 |
| 1-2 운동 목표와 달성률 | `TECH-600` 기획, 서브이슈 33건 계획 중 실제 생성은 3건(`TECH-601` 카탈로그, `TECH-602` 달성률 산식, `TECH-604` 화면기획) — BE 9건(B1~B9)은 미발행 | 아래 상세 참고 |
| 1-3 캘린더 및 주간 계획 | Linear 이슈 없음 (프로젝트 설명에만 정의) | 착수 조건: 1-1 기록 데이터 모델 확정 + 목표 요일/시간 개념 필요. 세부 기획 나오기 전까지 대기 |
| 1-4 운동 요약 이미지 | `TECH-571~574` 리서치/기본기획 진행 중, 전부 이상진 담당 | 백엔드 관점 이슈 아직 없음 — 기록 데이터 → 이미지 생성 API, 뱃지 연동 범위는 확인 필요 (03 참고) |
| 1-5 푸시 알림 리마인드 | Linear 이슈 없음 | 트리거 데이터(1-1~1-4)가 선행이라 순서상 마지막에서 두 번째. 예약 발송 인프라 · 피로도 제어 기준은 세부 기획 대기 |
| 1-6 코치마크 및 튜토리얼 | Linear 이슈 없음 | 선행조건: 1-1~1-5 배포 완료. 화면 확정 후 계측 이벤트 지원 정도로 우선순위 낮음 |

### 1-1 상세 — 백엔드 개입 지점

- [ ] 완료 확정 + 세트값(무게·횟수, 시간 단위 운동은 시간) 저장 스키마 설계 — **스키마 변경은 1회만 가능**하므로 향후 파생값(부위별 볼륨, 달성률 원천)까지 미리 고려해 확정
- [ ] 오염원 3건 선행 차단 로직: 자동 저장 방지 · lb→kg 단일화 · 총무게 산식 통일
- [ ] 배포 전후 운동 시간 지표 분리 산출 로직 (과거 데이터 소급 보정이 없어 시계열이 끊기는 것에 대응)
- [ ] 기구 선택 화면의 "과거에 많이 했던 기구 순" 정렬 API, 세트 입력 시 최신 기록 미리 채움 API
- [ ] 미리 채움 값을 그대로 확정하는지 여부를 구분 계측하는 필드/로그 설계 (D+7 비율로 사후 판단하기 위함)
- ⚠️ 이 스키마가 `TECH-600` 목표/달성률의 선행 조건 — 확정 전에 목표 쪽 B1(엔티티 설계)과 일정을 맞춰야 함

### 1-2 상세 — `TECH-600` BE 9건 (미발행, 발행 자체가 할 일)

| # | 내용 | 선행 |
|---|---|---|

| B5 | 목표 등록 — 1인 1개 강제 + 기존 비활성화를 한 트랜잭션으로 | B4 |

- ⚠️ 인바디 API 연동이 2024-11-22 이후 중단 상태 — 1단계에서는 체성분 기반 달성률 불가
