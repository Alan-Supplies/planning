# Alan 실행 순서 — 데이터 자산화 P0

> 출처: `supplies-data-plan-summary.md` (착수일 2026-07-28). Alan(BE) 관점에서 "지금 내가 해야 할 일"만 추려 순서를 매긴 문서.

## 요약

가장 먼저 **보안 핫픽스(IDOR, P0-06)**를 막고, 동시에 **임계경로의 시작점인 round_number 정합화(P0-10)**를 착수한다. 정의 확정(Vonn)·클라 수정(Jenna)은 병렬로 진행되므로 기다리지 않는다. W2에 KST 헬퍼→TZ버그 3건을 순차 처리하고, W3에 **gymboxx-lib 4.29.0 + DDL 배포(P0-11)**로 임계경로를 닫는다. W4 게이트 판정 통과 후 P1(Alan 15건)로 넘어간다.

## 순서대로 할 일

### 지금 즉시 (W1, D+1~5)

1. **DA-P0-06 — 운동세션 소유자 검증 누락(IDOR) 핫픽스**
   - 판정: G2(법적·보안, 누적형). 문서상 "최우선"으로 명시됨.
   - 왜 1번: 방치할수록 침해 범위가 누적되는 보안 결함이라 지연 비용이 가장 크다.

2. **DA-P0-10 — round_number 중복 사전 정합화 착수**
   - 판정: G3. **임계경로 시작점** (P0-10 → P0-11이 P0 전체 소요를 결정).
   - 왜 지금: 실측이 필요해 소요가 길다. 나중에 시작하면 전체 일정이 그만큼 밀린다. W1에 시작해 W2에 완료해야 W3의 lib 배포가 막히지 않는다.

3. **DA-P0-02 — started_at 의미·채우기 규칙 확정 (Vonn과 공동)**
   - 판정: G4+G1. Vonn이 최종 결정권자지만 Alan도 공동 담당.
   - 왜 지금: 이 규칙이 확정돼야 다음 단계의 KST 헬퍼(P0-03) 구현이 가능하다.

4. **DA-P0-12 — 이벤트→DB 조인 경로(BigQuery Export) 착수**
   - 판정: G3. Vonn과 공동.
   - 왜 지금: W1 착수 → W2 완료가 명시된 일정. 착수를 늦추면 W2 완료가 불가능해진다.

5. **DA-P0-15 — 심야·광고성 푸시 즉시 차단 (Vonn과 공동)**
   - 판정: G2(법적 리스크, 정보통신망법 위반 소지).
   - 왜 지금: 코드 변경 없이 **배치 cron 시각만 KST 08~21시로 이동**하면 되는 즉시 조치. 법무 의뢰도 병행해서 접수까지만 하면 P0 DoD 충족(회신은 Wave2·5로 승계).

> 참고: 정의 미확정 항목(P0-01, Vonn 단독)과 클라 즉시수정(P0-07·08, Jenna)은 이 시점에 병렬로 진행 중이어야 한다 — 기다리지 않는다.

### W2 (D+6~10)

6. **DA-P0-03 — kstDayRange()·kstWeekRange()·kstToday() 단일 헬퍼**
   - 판정: G1+G4. **전제조건: P0-01(주 시작요일, Vonn)·P0-02(started_at 규칙) 확정 완료**.
   - 왜 이 순서: 이 헬퍼가 없으면 아래 두 TZ버그를 제대로 고칠 수 없다.

7. **DA-P0-04 — 스트릭 TZ버그 수정(T-3)**
   - 판정: G1(현재도 오염 진행 중, 소급 불가). P0-03 완료 후 착수.
   - 참고: CS의 "스트릭 수치 변경 사전공지" 협조가 선행되어야 함.

8. **DA-P0-05 — 챌린지 주경계·캘린더선택 버그(T-1·T-4)**
   - 판정: G1. P0-03 완료 후 착수, P0-04와 같은 헬퍼 위에서 처리.

9. **DA-P0-09 — 총무게 산식 정정(E-9) (Jenna와 공동)**
   - 판정: G1(현재도 오염 진행 중).

10. **DA-P0-10 — round_number 정합화 완료 / DA-P0-12 — BigQuery Export 완료**
    - W2 안에 두 항목 모두 마무리해야 W3의 lib 배포가 예정대로 간다.

### W3 (D+11~15)

11. **DA-P0-11 — gymboxx-lib 4.29.0 + DDL 배포 (스테이징 → 프로덕션)**
    - 판정: G3. **임계경로의 종점**. P0-10 완료가 이 작업의 선행조건.
    - 배포 순서: lib → DDL → server → batch → client(플래그 OFF) → 단계 개방.

### W4 (D+16~)

12. **P0 게이트 판정 대기 (Harvey) → 통과 시 Wave 1 착수 + P1 착수**
    - Alan의 P1 15건이 이 시점부터 시작된다.

## 병행 의존관계 노트

- **임계경로**: P0-10 → P0-11. 이 체인이 늦어지면 P0 전체가 늦어진다.
- **리스크**: Alan 1인에 P0 8건이 집중되어 있음 — 정의 4건(Vonn)·클라 3건(Jenna)을 독립 병렬로 분리해 완화하는 구조이므로, 그쪽 진행을 기다리며 대기하지 말 것.
- **법무 회신 지연 대응**: P0-15/16은 "의뢰 접수"까지만 하면 DoD 충족. 회신 자체는 Wave 2·5 블로커로 넘어간다.

## 이 트랙에서 하지 않는 일 (2단계 이후, 착수 안 함)

- L3(DW) 구축, L4(CDP) 본격화, 지표 레이어, 결제 도메인 분리 등 P2 12건 — 착수 조건 5개 충족 전까지 티켓조차 발행하지 않음.
