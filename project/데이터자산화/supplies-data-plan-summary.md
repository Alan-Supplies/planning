# 데이터 자산화 기획안 — 핵심 요약 (실행 가능한 것 위주)

> 원문: `supplies-data-plan.md` (4046줄) 요약본. 착수일 2026-07-28.

## 한 줄 요약

DB(정본)·이벤트(행동)·DW(분석)·CDP(활성화) 4계층 중 이번 1단계는 L1(DB)·L2(이벤트) 정비에 집중하고, L3(DW)·L4(CDP) 본격화는 도구 선정 후 2단계 이후로 이연한다. Wave 1 착수 전 반드시 끝내야 하는 **P0 17건**(선행 게이트, 결함 49건 중 법적 리스크 2건 포함)이 지금 당장의 실행 대상.

## 계층별 실행 항목 (L1/L2/L3/L4)

- **L1 (DB)**: 신규 테이블 21종(마스터4+사용자데이터17) + 기존 테이블 변경 3종을 gymboxx-lib 4.29.0/4.30.0/4.31.0 열차로 배포. 결함 49건 중 P0 즉시 처리. 신규 21종 전부 user_id 보유 또는 마스터, JSON 집계 컬럼 0건.
- **L2 (이벤트)**: 97종 택소노미 확정 완료 → 이벤트 명세 대장 가동(DA-P0-14), logEvent() 래퍼로 user_id 등 공통 프로퍼티 자동 주입(DA-P1-02), 스크린 레지스트리 v1로 screen_name 단일화(DA-P0-13), BigQuery Export 연결·DB조인 실증(DA-P0-12).
- **L3 (DW)**: 착수 안 함. 진입조건 5개(Wave1~6 D+30 안정화, 이벤트97종 수신검증, 용어사전 등재, 도구선정 완료, 이벤트-DB 조인 경로 확보) 전부 충족 후 3단계(DA-P2-02)에서 착수.
- **L4 (CDP)**: push_schedule + PushGateway + push_delivery_log가 이미 1차 구현체. 지금은 세그먼트 정의가 DW가 아니라 배치쿼리 안에 있는 한계만 있음 — 본격화(DA-P2-04)는 도구선정(DA-P2-01) 후.

## 확정된 일정/배포 순서

**gymboxx-lib 릴리스 열차 (3열차, 확정 규칙)**
1. **4.29.0**: 운동기록 세션컬럼 + 신규 엔티티 17종(템플릿3·프로그램2·대체1·목표9·캘린더2). ALTER는 반드시 1회로 통합. 합류순서: 운동기록→운동세트→운동목표→캘린더.
2. **4.30.0**: 푸시 신규 엔티티3종+notification 컬럼2개. 4.29.0 배포 후 **D+7 안정화 확인 뒤** 진행. messaging-lambda는 server보다 먼저 올려야 함.
3. **4.31.0**: 코치마크·튜토리얼(UserTutorialProgressEntity).
- gymboxx-pass-server(3.6.1)는 전 열차 승격 불필요.
- 배포 순서: 4.29.0 = lib→DDL→server→batch→client(플래그OFF)→단계개방 / 4.30.0 = lib→DDL→messaging-lambda→server→batch(PUSH_DRY_RUN=true 1주)→client→실발송 / 4.31.0 = lib→DDL→server→client.

**주차별 배치 (착수 2026-07-28, 영업일 기준)**
- **W1(D+1~5)**: 보안핫픽스(P0-06 최우선) · 정의2건(P0-01·02) · 법무의뢰3건 발송(P0-15·16) · 클라 즉시수정(P0-07·08) · round 실측시작(P0-10) · BigQuery 착수(P0-12)
- **W2(D+6~10)**: KST헬퍼(P0-03)→TZ 3건(P0-04·05) · 총무게(P0-09) · round 완료(P0-10) · BigQuery 완료(P0-12) · 레지스트리 착수(P0-13)
- **W3(D+11~15)**: **lib 4.29.0 + DDL 실행**(P0-11, 스테이징→프로덕션) · 레지스트리 완료→명세대장(P0-14) · 용어사전(P0-17)
- **W4(D+16~)**: P0 게이트 판정(Harvey) → Wave 1 착수 + P1 본격 가동
