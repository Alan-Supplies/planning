# Phase 0 — 도구 익히기

작성: 2026-09-02 / 상위 문서: [PLAN.md](./PLAN.md)

## 이 단계의 목표

"C#을 배운다"가 아니다. **클릭한 타일로 스프라이트 하나가 움직이는 씬을 내 손으로 띄운다**이다.
Unity 에디터와 C#이 더 이상 낯설지 않은 상태가 되면 끝난 것이고, 그 판정은 아래 종료 판정으로 한다.

예산: 6주 × 5시간 = 30시간.

## 환경 실측 (2026-09-02)

| 항목 | 상태 | 조치 |
|---|---|---|
| Unity Hub | 미설치 | W1에 설치 |
| Unity Editor | 미설치 | W1에 LTS 설치 |
| `dotnet` | 설치됨 (homebrew) | 그대로 사용 — W1~W2 C# 연습에 씀 |
| VS Code | 설치됨 | C# Dev Kit + Unity 확장 설치 |
| 디스크 여유 | 52GB | 모듈 최소만 골라 설치 |

### 설치 시 주의

- **Editor 모듈은 최소만.** Mac Build Support 하나만 체크하고 iOS/Android/WebGL/Linux는 전부 뺀다.
  전부 넣으면 20GB를 넘고, Steam(Mac/Windows) 외에는 쓸 일이 없다.
- **버전은 Unity Hub에서 LTS(권장)로 표시된 6.x**를 고른다. 최신 프리뷰를 고르면 튜토리얼·검색 결과와 화면이 어긋난다.
- **프로젝트 경로와 프로젝트명은 영문으로.** Unity는 한글 경로에서 간헐적으로 문제를 만든다.
  게임 프로젝트는 이 플래닝 저장소에 두지 않는다 (Unity의 `Library/`가 수 GB다).
  위치 제안: `~/workspace/supplies/samgukji-tactics` — Unity Hub가 이 경로에 직접 만들게 한다.

## 주차 계획

각 주의 "남아야 하는 것"은 다음 주에 내가 확인할 수 있는 형태여야 한다. 없으면 그 주는 안 한 것으로 본다.

### W1 — 환경 + C# 문법 1 (Unity를 켜지 않는다)

- Unity Hub 설치 → Unity 계정 생성 → Editor(LTS) 설치까지만. 프로젝트는 만들지 않는다.
- VS Code에 C# Dev Kit 확장 설치.
- 콘솔 C#으로 문법 1탄: 변수, 타입(`int`/`float`/`string`/`bool`), 조건, 반복, 메서드.
- TypeScript와 다른 지점만 골라 익힌다: 정적 타입 강제, `var`의 의미 차이, `int`/`float` 구분, `null` 처리.

남아야 하는 것: `dotnet run`으로 돌아가는 콘솔 프로그램 하나.

### W2 — C# 문법 2 (여전히 Unity를 켜지 않는다)

- 클래스, 필드/프로퍼티, `enum`, `List<T>`, `Dictionary<K,V>`.
- **연습 대상을 이 게임의 데이터 모델로 잡는다.** 무장(이름/HP/공격/이동력/병종), 타일(좌표/지형),
  유닛 목록, 좌표로 타일 찾기, 데미지 계산 함수 하나.
- 이걸 콘솔에서 먼저 만들어두면 Phase 1은 여기에 그림만 붙이는 일이 된다.

남아야 하는 것: 콘솔에서 "유닛 A가 유닛 B를 공격 → HP 감소 → 사망 판정"이 텍스트로 출력된다.

### W3~W4 — Unity Essentials Pathway 완주

- 공식 [Unity Essentials Pathway](https://learn.unity.com/pathway/unity-essentials)를 쓴다.
  무료, 선수 지식 없음, Unity 6 기준으로 최신이고, 다루는 범위가 이 단계의 목표와 정확히 겹친다
  (에디터 조작, GameObject, Component, Prefab, 기본 스크립팅, 물리, 빌드).
- **끝까지 완주한다.** 완전 초보 구간에서 "필요할 때 검색"은 함정이다. 검색 학습은 W5부터 시작한다.
- 만드는 결과물이 이 게임과 안 닮았다고 중간에 갈아타지 않는다. 배우는 건 에디터 감각이다.

남아야 하는 것: Pathway 수료 + 씬을 빌드해서 실행 파일로 한 번 띄워보기.

### W5 — 격자 그리기 (튜토리얼 없이)

- 새 2D 프로젝트에서 10x10 격자를 화면에 띄운다. Tilemap을 써도 되고 스프라이트를 코드로 배열해도 된다.
- 여기서 처음으로 "막히면 검색"으로 전환한다.

남아야 하는 것: 실행하면 10x10 격자가 보인다.

### W6 — 클릭 → 좌표 → 이동

- 마우스 클릭 위치를 타일 좌표(예: `(3, 5)`)로 변환해서 콘솔에 찍는다.
- 그 좌표로 스프라이트 하나를 순간이동시킨다. 애니메이션·보간은 하지 않는다.

남아야 하는 것: **종료 판정 통과.**

## 종료 판정

전부 예여야 Phase 1로 넘어간다. 하나라도 아니면 그 항목만 1~2주 더 한다.

- [ ] 새 2D 프로젝트를 처음부터 만들고, 스프라이트를 씬에 올리고, 스크립트를 붙여 움직일 수 있다
- [ ] `MonoBehaviour`의 `Start`와 `Update`가 언제 호출되는지 설명할 수 있다
- [ ] Prefab이 뭐고 왜 쓰는지 설명할 수 있다
- [ ] Inspector에 내가 만든 변수를 노출시키고 값을 바꿔 동작이 변하는 걸 확인할 수 있다
- [ ] 클래스, `List`, `Dictionary`를 보고 막히지 않는다
- [ ] 마우스 클릭 위치를 타일 좌표로 바꿀 수 있다
- [ ] 에러 메시지를 읽고 어느 파일 몇 번째 줄인지 찾아갈 수 있다

## Phase 0에서 하지 않을 것

손대고 싶어지는 순서대로 적어둔다. 전부 Phase 1 이후다.

- 아트, 캐릭터 일러스트, 도트 스프라이트 구매
- 스토리, 시나리오, 무장 설정
- 애니메이션, 파티클, 셰이더, 사운드
- UI 디자인, 폰트
- 3D, 세이브/로드, 최적화
- 에셋스토어 구경 (특히 이거)

## 진행 방식

- 주 5시간을 **90분 이상 세션 2~3회**로 쪼갠다. 30분씩 열 번으로 나누면 초보 구간에서는 매번 맥락 복구에만 시간을 쓴다.
- 세션 끝마다 `progress.md`에 한 줄 남긴다. 다음 세션의 시작 비용이 여기서 결정된다.
- 세션 끝에는 항상 "돌아가는 상태"로 남긴다. 반쯤 고친 코드로 끝내면 다음 주에 복귀하지 못한다.
