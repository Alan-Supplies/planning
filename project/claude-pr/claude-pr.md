[컨텍스트: Slack 요구사항 자동화 프로젝트]

1. 모델 정보 (2026-07-08 기준, 검색으로 확인함)
- Claude Fable 5는 Opus보다 상위 등급("Mythos-class")이다. Anthropic이 공개한 모델 중 가장 성능이 높음.
- 가격: 입력 $10/M, 출력 $50/M (Opus보다 비쌈). 1M 컨텍스트, 최대 128k 출력.
- 특징: 작업이 길고 복잡할수록(장기 자율 작업, 멀티스텝 계획, 서브에이전트 위임, 자기검증) Fable의 우위가 커짐. 단순 작업엔 오히려 비효율(과한 비용).
- 참고: https://www.anthropic.com/news/claude-fable-5-mythos-5

2. 비교 중인 아키텍처: Slack 요구사항 채널 → PR 자동 생성
옵션 1) Slack 훅 → Claude API 직접 호출 → 코드 생성 → CLI(git/gh)로 PR 생성
  - 장점: 요청별로 모델을 세밀하게 골라 쓸 수 있음 (단순=저가모델, 복잡=Fable)
  - 단점: 레포 컨텍스트를 스스로 못 봄 → 실제 쓸만한 코드 만들려면 파일탐색/도구호출 루프를 직접 구현해야 함(사실상 에이전트 재구현). 안 하면 품질 낮아 리뷰 반려율↑ → 숨은 재작업 비용.

옵션 2) Claude Code/Desktop + Slack 연동 → 에이전트가 직접 탐색·구현·PR 생성
  - 장점: 파일탐색/코드작성/git 툴체인 이미 갖춰져 있음. 품질 높고 구축 공수 적음.
  - 단점: 세션마다 컨텍스트(레포 탐색 등) 로딩돼서 단순 요청에도 토큰 비용이 상대적으로 큼. 요청 단위 세밀한 모델 라우팅은 어려움.

3. 내가 정한 조건
- 효율 기준 = 비용(토큰/API) 최우선
- 요청 물량 = 아직 미정, 앞으로 증가 예정
- PR 머지 전 사람 리뷰는 항상 필수 (완전 자동 정확도에 과투자 불필요)

4. 결론(추천안): 하이브리드
- 저가 모델(Sonnet/Haiku)로 Slack 메시지를 먼저 "단순 vs 복잡" 분류
- 단순 요청(텍스트/설정값 등 컨텍스트 거의 불필요) → 옵션1 방식으로 저비용 단발 처리
- 복잡 요청(여러 파일 탐색/수정 필요) → 옵션2 방식(필요시만 Fable)으로 처리
