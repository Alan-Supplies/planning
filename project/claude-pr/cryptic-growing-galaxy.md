# Fable급 작업 탐색 문서 작성
## 주의
지라를 더 이상 쓰지 않는다.
리니어로 이전 했다.

## Context

지금까지 Slack 요구사항→PR 자동화 프로젝트를 논의하며 "Fable 5는 장기·다단계·모호한 작업일수록 유리하고, 단순 작업엔 비효율적"이라는 모델 라우팅 기준을 세웠다. 이 기준을 한 프로젝트에 국한하지 않고 **회사 전체 워크플로우**에 적용해, "어떤 기존/진행 중 작업이 Fable급인가"를 실제로 찾아내는 방법이 필요해졌다.

찾는 방법은 Slack과 이슈 트래커를 검색하는 것으로 정했다. 다만 현재 세션에는 Slack/이슈 트래커 MCP 커넥터가 연결되어 있지 않음을 확인했다(`mcp-registry` 검색 결과 0건, 설치된 커넥터도 0건). 따라서 이번 결과물은 **사람이 직접 Slack/이슈 트래커 검색창에 붙여넣어 쓰는 문서**(판단 기준 + 검색 쿼리 모음)이며, 실제 자동화(API/MCP 연동)는 다음 단계로 명시만 하고 이번 범위에서 제외한다. 판단 기준은 새로 만들지 않고 기존에 합의한 기준(장기 호라이즌·다단계 계획·모호성·교차 서비스 범위·서브에이전트 위임 유용성·실패 비용)을 재사용한다.

Vault(`/Users/sungwookkim/workspace/docs`, Obsidian)에는 아직 이런 유형의 문서가 없다 — infra 주제별 폴더(`fluent bit/`, `kubenetes/`)만 존재하고, frontmatter/Properties는 쓰지 않으며, 문서는 두 스타일(구조화된 트러블슈팅 문서 / terse 체크리스트 + 해시태그)이 섞여 있다.

## 산출물

새 폴더 `AI/`를 만들고 그 안에 문서 1개를 작성한다.

**경로:** `/Users/sungwookkim/workspace/docs/AI/Fable급 작업 찾는 법.md`

`fluent bit/`, `kubenetes/`와 같은 레벨의 새 폴더로, 인프라 축이 아닌 "워크플로우/도구 라우팅" 축의 문서를 담는다. 이후 모델 계층 노트나 Slack→PR 자동화 노트가 추가되어도 이 폴더에 자연스럽게 모인다.

## 문서 구조 및 내용

기존 두 스타일을 혼합: `Parser.md`의 H2 한글 헤딩 + 코드펜스 + `## 참고` 섹션, `설정.md`의 frontmatter 없이 trailing 해시태그(`#claude_routing`). 스코어링 표는 vault에 없던 요소지만 순수 마크다운 테이블로 자연스럽게 추가.

섹션 순서:

1. `# Fable급 작업 찾는 법`
2. `## 배경` — Fable 5 위치/가격/특성 요약 3~4줄(현재 이 사실이 vault 어디에도 없으므로 인라인으로 남김) + 이 문서의 목적(회사 전체 워크플로우 대상, 기존 기준 재사용) 명시
3. `## Fable-class 판단 기준 (스코어링)` — 6개 기준(작업 기간/계획 복잡도/모호성/범위/서브에이전트 위임 유용성/실패·재작업 비용) × 0/1/2점 표
4. `## 종합 판정 기준` — 8~12점 Fable 후보 / 4~7점 경계선(Sonnet 시도 후 에스컬레이션) / 0~3점 Sonnet·Haiku로 충분
5. `## Slack 검색 쿼리` — 코드펜스로 실제 붙여넣을 쿼리 예시(날짜 범위, "여러 단계"/"multi-step", "여러 서비스"/"cross-service", 마이그레이션/리팩터링 키워드, 인시던트 채널 등) + Slack엔 스레드 길이 필터가 없다는 점과 수동 스캔 휴리스틱(답글 15+, 3일+ 지속, 참여자 3명+) 명시. 검색 연산자는 워크스페이스/요금제에 따라 다를 수 있다고 각주.
6. `## 이슈 트래커 검색 쿼리`
7. `## 사용 방법 (실행 절차)` — 위 쿼리들을 주기적으로 돌려서 스코어링표에 대입 → 8점 이상만 후보로 추림, 이런 실행 흐름을 짧게 정리
8. `## 다음 단계: 자동화` — 지금은 수동 검색이고, 다음 단계는 Slack + 이슈 트래커 MCP 커넥터 연결해서 스코어링을 스크립트/에이전트로 자동화하는 것(현재 미설치)이라고 2~3줄로 명시
9. `## 참고` — 이 대화에서 나온 근거(모델 발표 페이지 등, 있으면) 정리
10. 마지막 줄에 `#claude_routing` 태그

## 검증

- Obsidian에서 파일이 정상 렌더링되는지 확인 (특히 마크다운 테이블, 코드펜스 언어 태그 없는 블록)
- 새로 만든 `AI/` 폴더가 vault 탐색기에 노출되는지 확인
- 문서 내 예시 Slack/이슈 트래커 쿼리 문법이 실제 각 도구의 검색 문법과 어긋나지 않는지 육안 검토 (실제 워크스페이스 연결 전이므로 실행 테스트는 불가 — 문서 자체 정합성만 확인)
