## 이슈 & 회고

### 주문 데이터 불일치
- **상황:** 시간대별 매출이 기존 DB(Firestore)와 새 DB가 맞지 않음
- **삽질:** DB 비교 쿼리 작성, 데이터 추출 등에 시간 소비
- **원인:** 중복 주문으로 인해 매출이 더 잡힘
- **배운 점:** 해당 시간대 주문만 눈으로 확인했으면 바로 파악 가능했다

> "잠깐, 원본 데이터 10건만 눈으로 보자" — 이 한 마디가 2시간을 아껴준다.

**체크리스트 (데이터 이슈 발생 시)**
1. raw 데이터 직접 확인
2. `COUNT(*)` 먼저 — 건수 차이 확인
3. 중복 확인 쿼리 실행
4. 그 후에 복잡한 비교 작업

**중복 방지 설계**
- 주문 ID 기반 `UPSERT` 또는 중복 체크 로직 적용
- 검증 쿼리:
  ```sql
  SELECT order_id, COUNT(*) 
  FROM orders 
  GROUP BY order_id 
  HAVING COUNT(*) > 1;
  ```
