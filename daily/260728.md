## image-updater
PR #34 생성 완료: https://github.com/suppliesfitness/platform-iac/pull/34

이후 진행 순서

1. platform-iac PR #34 — 지금 올림
이미 AWS/클러스터에 apply된 내용을 git에 반영하는 것이라 실질적 신규 변경은 없습니다. 머지 리스크 낮음.

2. platform-gitops — 두 PR의 관계 확인
merge 시뮬레이션으로 확인한 결과, PR #13(9개 서비스 확산, 기존에 열려있던 것)과 PR #14(image-updater 애노테이션, 제가 올린 것)은 서로 다른 부분을 건드려 충돌 없이 깔끔하게 합쳐집니다. 그리고 중요한 점 — appset의 template 블록은 전 서비스가 공유하는 구조라, 두 PR이 모두 머지되면 나머지 9개 서비스도 자동으로 같은 애노테이션을 상속받습니다. 지난 턴에 "9개는 별도 작업 필요"라고 했던 건 정정합니다 — 불필요합니다.

머지 순서는 상관없지만, PR #13은 제가 연 게 아니고 체크리스트(docs/deployment/gymboxx-dev-온보딩-체크리스트.md)에 [ ] 8. 나머지 서비스 element 추가가 아직 미체크로 남아있어 — 아직 리뷰/검증 중인 별도 작업으로 보입니다. 그래서 그건 건드리지 않았고, 머지는 두 분 판단에 맡기겠습니다.

3. 머지 후 검증 (PR #14만 먼저 머지되어도, #13과 함께 머지되어도 동일)
kubectl logs -n argocd -l app.kubernetes.io/name=argocd-image-updater --tail=50 --context=arn:aws:eks:ap-northeast-2:699016088228:cluster/eks_dev
considering 0 → considering N annotated application(s)로 바뀌는지 확인 (N=1이면 #14만 머지, N=10이면 #13도 함께 머지된 상태).

4. write-back 확인
ECR dev의 최신 태그가 values-dev.yaml보다 새로우면 최대 2분 내 build: automatic update of gymboxx-<service>-dev 커밋이 platform-gitops에 올라옵니다. 그 뒤 Application이 OutOfSync가 되면 수동 sync로 배포 확인 → 안정되면 appset에 syncPolicy.automated 추가(체크리스트 항목 9)로 완전 자동화.

merge는 제가 임의로 누르지 않았습니다 — 두 platform-gitops PR 모두 실제 gymboxx 워크로드 배포에 영향 주는 액션이라, 준비 상태만 확인해뒀고 실행 버튼은 남겨뒀습니다. 원하시면 지금 바로 머지하겠습니다.
