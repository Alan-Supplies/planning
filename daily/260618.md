## 메모: AI 코딩툴 경험차이 (cursor+gpt5.5 vs claude code)
같은 "AI 코딩"인데 한쪽은 90% 맡기고 한쪽은 못 믿는 이유. 모델 차이만으로는 설명 안 됨.
체감을 가르는 건 (툴 통합도) × (검증 루프) × (코드베이스 성격) × (AI 운용 스킬) × (작업 유형)의 곱.

1. **툴 작동 방식**: Cursor는 인덱싱·자동 컨텍스트·린트 피드백·diff 검토가 IDE에 통합 → AI가 현재 상태 보고 자가 검증. Claude Code는 강력하지만 컨텍스트 세팅이 사용자 손에 달림.
2. **검증·피드백 루프(★핵심)**: 테스트/타입체커/린터/CI가 있으면 AI가 틀려도 스스로 수렴. 없으면 그럴듯하게 틀린 코드를 그대로 받음. 90% 위임 = 검증 루프가 탄탄하다는 신호.
3. **코드베이스 성격**: 컨벤션 일관·패턴 반복 → 적중률 높음. 레거시·암묵규칙·미문서 도메인지식 → 헛다리.
4. **작업 쪼개기/지시 방식(메타스킬)**: 작게 쪼개 명확한 목표·제약 제공, 규칙파일(.cursorrules/AGENTS.md)로 컨벤션 고정, 컨텍스트 동봉. "코딩 실력"이 아니라 "AI 운용 실력".
5. **"잘한다"의 기준 차이**: boilerplate/CRUD/리팩터/테스트(AI 강점) vs 아키텍처 결정·동시성·성능(AI 약점). 측정 대상이 서로 다름.
6. **신뢰 보정**: 잘 쓰는 쪽은 "AI=초안, 검증=시스템/나"로 역할분담. 못 믿는 쪽은 한두 번 데이고 신뢰 통째로 거둬 악순환.

결론: "GPT5.5라서"가 아니라 **AI가 실수해도 안전하게 수렴하는 환경 + 그걸 만들 줄 아는 사람**의 조합. 상대도 같은 환경·습관 갖추면 모델 무관하게 체감 달라질 가능성 높음.
