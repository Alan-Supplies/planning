## 목표 달성일 기준: 세션 시작일로 한다
- 현재: 운동 세션을 종료한 날짜로 달성이 기록된다.
  - 예) 9/28 23:30 시작 → 9/29 00:20 종료 ⇒ 9/29 달성으로 기록
- 문제
  - 사용자는 "어젯밤에 운동했다"처럼 종료한 날보다 시작한 날을 기준으로 기억한다.
  - 달력에서 볼 때 출석한 날(9/28)과 달성이 찍힌 날(9/29)이 어긋나 보인다.
- 대처
  - 달성률 계산은 지금처럼 세션을 종료할 때 하되, 어느 날짜의 달성으로 칠지는 세션 시작일(KST)로 한다.

## 목표 생성/변경 API 분리 (따닥 대처)
- 현재: 목표 생성 API 하나가 두 역할을 한다.
  - 진행중 목표 없음 → 생성
  - 진행중 목표 있음 → 기존 목표 중단 후 생성
- 화면별 흐름
  - 홈: 목표 유무에 따라 "생성"/"변경" 버튼이 나뉘어 있다.
    변경은 "진행중인 목표가 중단됩니다" 확인 모달을 거친 뒤 API 를 호출한다.
  - 마이페이지 > 목표내역: + 버튼 하나다. 누른 뒤에야 진행중 목표 유무에 따라
    바로 생성하거나, 중단 확인 모달을 띄운 뒤 API 를 호출한다.
- 문제: 진행중 목표가 없을 때 생성 버튼을 빠르게 두 번 누르면(따닥)
  1. 1번째 요청: 목표 A 생성
  2. 2번째 요청: A가 진행중이므로 A 중단 → B 생성
  - 사용자는 목표를 한 번 만들었는데, 확인 모달도 없이 중단된 목표가 생긴다.
  - API 가 하나라 서버는 2번째 요청이 모달을 거친 정상적인 변경인지 중복 호출인지 구분할 수 없다.
- 제안
  1. 목표내역의 + 버튼을 진행중 목표 상태에 따른 CTA 로 바꾼다.
     - 진행중 목표 없음: [목표 생성]
     - 진행중 목표 있음: [목표 변경] → 중단 확인 모달 → 변경 API
  2. 변경 API 를 새로 추가하고, 생성 API 는 진행중 목표가 있으면 거절한다.
     따닥의 2번째 생성 요청은 A가 이미 진행중이라 거절된다.
  - 변경 API 의 따닥은 API 분리 후 별도로 처리할 예정이라 이 문서에서는 다루지 않는다.
