# 출석하기 → ACCESS 소켓 수신 → 운동 세션 진입 흐름

> 홈 화면 "출석하기" 버튼부터 바코드 출석이 완료되어 앱이 WebSocket으로 `ACCESS` 이벤트를 받고
> 운동부위 선택 화면으로 넘어가기까지의 전 구간 기록. 앱(`gymboxx-user-app`) · 소켓 서버(`app-web-socket`) ·
> 출입 서버(`gymboxx-pass-server`) 세 레포에 걸쳐 있어 한 곳에서 추적하기 어려운 흐름이라 정리해 둔다.
>
> 기준 시점: 2026-08-11 / `production` 브랜치

## 요약 (TL;DR)

```
[홈] 출석하기 버튼
  → 디바이스 검증(deviceValidation)  ← MISMATCH면 로그아웃
  → 바코드 모달 오픈 (이때 WebSocket 연결됨)
  → [키오스크] 바코드 스캔
      → gymboxx-pass-server  handleAccessHistory()
        → HTTP GET  {APP_WEB_SOCKET}/today-workout/{userId}?access_history_id=..&gym_id=..
          → app-web-socket  message-to-one Lambda
            → DynamoDB에서 connectionId 조회 → postToConnection
  → 앱 ws.onmessage  type === "ACCESS"
      ├ 훅:   출석기록 캐시 무효화 + (지점 다르면) 지점 변경 Alert + setData
      └ 모달: 모달 닫기 + 진동 → 100ms 후 분기
              ├ 짐세권 설문 미응답 && 프로 회원권 아님 → /app/location-survey
              └ 그 외 && access_history_id 있음      → /app/exercise/body-part  ← 운동 세션
```

## 4. 서버 — app-web-socket

AWS API Gateway WebSocket + Lambda + DynamoDB(serverless framework). 같은 워크스페이스의 `web-socket-server`는 **socket.io 기반 관리자 전용**이라 무관하다(앱은 raw `new WebSocket`이라 프로토콜 자체가 안 맞는다).

| 함수 | 트리거 | 하는 일 |
| --- | --- | --- |
| `websocketConnect` | ws `$connect` | `user_id`·`gym_id` 쿼리 필수(없으면 500). **동일 userId의 기존 커넥션을 전부 지운 뒤** 신규 등록 |
| `websocketDisconnect` | ws `$disconnect` | 커넥션 삭제 |
| `messageToOne` | **HTTP GET** `/today-workout/{userId}` | `ACCESS` 발송 — 이 흐름의 핵심 |
| `messageToAll` | ws route `toAll` | 같은 지점 전체에 `UPDATE` 발송 (앱에서 미사용) |

**`messageToOne`은 WebSocket route가 아니라 일반 HTTP 엔드포인트다.** 앱이 뭘 보내서 받는 구조가 아니라, 백엔드가 REST로 찔러 넣으면 Lambda가 DynamoDB에서 해당 유저의 `connectionId`를 찾아 push한다.

## 5. 서버 — 트리거 (gymboxx-pass-server)

`UserService.handleAccessHistory()` → `pingWebSocketServer(userId, gymId, accessHistoryId)`

```ts
url: `${appWebSocketEndpoint}/today-workout/${userId}?access_history_id=${accessHistoryId}&gym_id=${gymId}`
```

| `ACCESS_TYPE` | 소켓 ping |
| --- | --- |
| `ACCESS` (당일 첫 출석) | ✅ |
| `REVISIT` (재방문) | ✅ |
| `REENTER` (재입장) | ❌ |
| `EXPIRED` | ❌ |

두 가지 주의점:

- `pingWebSocketServer`는 **실패해도 catch로 삼키고 로그만 남긴다.** 출입 처리는 성공했는데 앱에는 아무 일도 안 일어나는 상황이 여기서 나온다.
- 서버는 `REVISIT`도 `type: "ACCESS"`로 보낸다. **앱은 첫 출석과 재방문을 구분할 수 없다.**
- `APP_WEB_SOCKET_ENDPOINT`는 pass-server의 k8s ConfigMap `env`에 있다(레포에 값 없음).

## 6. ACCESS payload 스펙

`app-web-socket`의 `getWorkoutResponse()` 결과를 `JSON.stringify`한 값이 그대로 온다.

```json
{
  "type": "ACCESS",
  "access_history_id": "2829",
  "access_date": "2026-08-10T22:44:55.654Z",
  "all_gym_workout": [],
  "current_gym_workout": {
    "CHEST": 0, "BACK": 0, "SHOULDER": 0,
    "ARM": 0, "LEG": 0, "CARDIO": 0
  },
  "gym_id": 494
}
```

| 필드 | 타입 | 앱 사용 | 비고 |
| --- | --- | --- | --- |
| `type` | `"ACCESS"` \| `"UPDATE"` | ✅ 훅 + 모달 | 출석은 항상 `ACCESS` |
| `access_history_id` | **string** | ✅ 모달 | 서버가 숫자 변환을 안 함 |
| `gym_id` | **number** | ✅ 훅 | 서버가 `+`로 변환 |
| `access_date` | ISO string | ❌ | 서버 수신 시각 |
| `current_gym_workout` | 부위별 비율 0~1 | ❌ | 소수 2자리 |
| `all_gym_workout` | `[]` | ❌ | 코드가 주석 처리되어 **항상 빈 배열** |

`gym_id`는 **반드시 number**여야 한다. 문자열이면 `parsedData.gym_id !== mainGym?.id`가 항상 참이 되어 출석할 때마다 지점 변경 Alert이 뜬다. 서버는 정상 변환하므로 수동으로 찔러 테스트할 때만 주의하면 된다.

## 7. 수신 후 동작

### 7-1. 훅 — [`useExerciseWebsocket.ts:50-73`](../src/hooks/useExerciseWebsocket.ts#L50-L73)

```ts
ws.onmessage = (e) => {
  const parsedData = JSON.parse(e.data)
  console.log("parsedData", parsedData)

  if (parsedData.type === "ACCESS") {
    dispatch(userApi.util.invalidateTags(["AccessHistory"]))

    if (parsedData.gym_id !== mainGym?.id) {
      Alert.alert(`선택 지점이 출석 지점으로 변경됩니다.`, "", [
        { text: "확인", onPress: () => {
            getGymData(parsedData.gym_id).unwrap()
              .then((res) => { dispatch(setMainGym(res.gym)) })
        }},
      ])
    }
  }
  setData(parsedData)   // ← ACCESS 분기 밖. 모든 메시지가 여기로
}
```

- `invalidateTags(["AccessHistory"])`는 `getAccessHistory` · `getLastAccessHistory` 캐시를 무효화해 **홈 캘린더 UI를 갱신하는 용도**다. `access_history_id`는 payload에 이미 들어 있으므로 이 refetch를 기다릴 필요가 없다.
- `Alert.alert`은 논블로킹이라 다음 줄 `setData`가 곧바로 실행된다. **지점이 달라도 화면 전환은 그대로 진행된다.**
- `setData`가 `ACCESS` 분기 밖에 있어 `UPDATE` 메시지도 저장하지만, 모달이 `type`으로 걸러낸다.

### 7-2. 모달 — [`BarcodeAndExerciseModal/index.tsx:148-170`](../src/components/Home/BarcodeAndExerciseModal/index.tsx#L148-L170)

```ts
if (!socketData || socketData.type !== "ACCESS") return

onRequestClose()          // 모달 닫기   ← 조건 없이 무조건
Vibration.vibrate(500)    // 진동        ← 조건 없이 무조건
setTimeout(() => {
  if (!locationSurveyStatus && membership?.type !== "ALL_SUBSCRIPTION") {
    router.push("/app/location-survey")
  } else if (socketData.access_history_id) {
    handleRouteToBodyPart(socketData.access_history_id)
  }
}, 100)
```

**모달 닫기와 진동은 조건 밖이다.** 조건은 100ms 뒤 라우팅 대상만 가른다.

`handleRouteToBodyPart`([:126-145](../src/components/Home/BarcodeAndExerciseModal/index.tsx#L126-L145)):

```
clearExerciseSession() → clearCompletedSession()
  → startExerciseSession([], accessHistoryId)   // AsyncStorage 세션 기록
  → exerciseWidget.startLiveActivity()          // iOS 라이브 액티비티
  → setLiveActivityId(activityId)
  → onRequestClose()
  → router.push("/app/exercise/body-part", { accessHistoryId })
```

### 7-3. 운동 세션으로 빠지는 조건

```
(locationSurveyStatus === true || membership?.type === "ALL_SUBSCRIPTION")
&& socketData.access_history_id 존재
```

`if / else if`라 **설문 분기가 먼저 걸리면 세션은 아예 시작되지 않는다.** 짐세권 설문으로 빠지면 제출 후 `/app/result/completion`으로 replace되어 그 회차 운동 세션은 건너뛴다.

| 변수 | 출처 |
| --- | --- |
| `locationSurveyStatus` | `GET /user/v2/{userId}/location-survey/status` → boolean |
| `membership?.type` | redux `state.membership.membership` |
| `access_history_id` | 소켓 payload |

`ALL_SUBSCRIPTION` = **프로 회원권**이다([`membership/peripheral/index.tsx:57`](../app/app/membership/peripheral/index.tsx#L57)의 `isProMembership`). 프로 회원은 짐세권 설문을 건너뛰고 곧장 운동 세션으로 간다.

## 8. 테스트 / 재현

### 8-1. 짐세권 설문 상태 조작

`getLocationSurveyStatus`는 [`user.dao.ts`](../../../../gymboxx-app-server/src/modules/user/user.dao.ts)에서 이렇게 판정한다.

```ts
const locationSurvey = await this.userLocationSurveyRepository.findOne({
  where: { user: { id: userId } },
})
return locationSurvey ? true : false
```

`gym_id`도 `version`도 조건에 없다. **유저 기준 행이 1건이라도 있으면 `true`다.**

```sql
-- 테이블: user_location_survey  (PK: gym_id + version + user_id, gym_id/user_id는 FK)
-- true로 만들기
INSERT INTO user_location_survey (user_id, gym_id, version)
VALUES (<user_id>, <gym_id>, 'v1');

-- 되돌리기 (설문 분기 재현)
DELETE FROM user_location_survey WHERE user_id = <user_id>;

-- 현재 상태 확인
SELECT user_id, gym_id, version, created_at
  FROM user_location_survey WHERE user_id = <user_id>;
```

- 건너뛰기(`POST /location-survey/skip`)도 같은 테이블에 행을 만든다. **스킵만 해도 `true`가 된다.**
- `location_survey`(좌표 통계)는 status 판정과 무관하므로 건드릴 필요 없다.
- dev DB에는 설문 이력이 11명(전부 `gym_id=5`, `v1`)뿐이라, 임의 테스트 계정은 대부분 설문 분기를 탄다.
- DB 접속 정보는 `~/.claude/gymboxx-db.md` 참조. 상용 readonly 계정은 `SELECT` 권한만 있어 INSERT/DELETE는 별도 계정이 필요하다.

가장 간단한 방법은 **프로 회원권 계정을 쓰는 것**이다. DB를 건드리지 않아도 세션 분기를 탄다.

## 9. 알려진 함정과 잔재

1. **`access_history_id`가 문자열로 온다.** `message-to-one.ts`에서 `gymId`는 `+`로 변환하는데 `accessHistoryId`는 그대로 쓴다. 앱이 truthy 체크 후 `Number()`로 감싸 쓰므로 지금은 무해하지만, `===` 비교를 넣으면 바로 깨진다.

2. **`toAll` / `UPDATE` 경로가 죽어 있다.** `sendWebSocketMessage`는 훅 → HOC → Context까지 전달되지만 **어디서도 호출되지 않는다.**

3. **`ExcerciseAreasContent`는 dead export다.** `BarcodeAndExerciseModal`에 운동부위 선택 UI(가슴/하체/등/팔/어깨/유산소)가 export되어 있으나 참조하는 곳이 없다. 운동부위 선택이 REST 기반 `exercise-session` API와 별도 화면으로 옮겨간 뒤 남은 잔재이며, 파일·컴포넌트 이름(`Barcode + Exercise`)도 그때의 흔적이다.

4. **재입장(`REENTER`)은 소켓이 오지 않는다.** 같은 날 재입장 시 모달이 안 닫히고 멈춰 있다면 이게 원인이다.

5. **모달의 `typeof socket.data === "string"` 방어 코드는 실행되지 않는다.** 훅이 이미 파싱한 객체를 넣기 때문이다.

6. **`useGetLocationSurveyStatusQuery`에 `providesTags`가 없다.** 어떤 mutation으로도 무효화되지 않으므로, DB를 고친 뒤에는 앱을 재시작해야 확실히 반영된다(기본 `keepUnusedDataFor` 60초).

7. **161행이 `"ALL_SUBSCRIPTION"` 문자열 리터럴을 직접 쓴다.** 같은 값이 [`Constants.tsx:44`](../src/utils/Constants.tsx#L44)에 상수로 있고 다른 화면은 전부 그쪽을 import한다.

8. **`app-web-socket/env.yml`에 dev/prod RDS 비밀번호가 평문으로 커밋되어 있다.** 레거시로 유지 중.

## 부록 — 실측 사례

dev에서 관측한 payload와 그때의 DB 상태.

```json
{ "type": "ACCESS", "access_history_id": "2829", "gym_id": 494, ... }
```

```
gym 5   = dev난곡점 (000005)      ← 앱의 mainGym
gym 494 = 테스트 지점 (000134)     ← 실제 바코드를 찍은 지점

access_history 2829
  user_id 51758 / gym_id 494 / method BARCODE / type ACCESS
  membership_type ALL_SUBSCRIPTION / created_at 2026-08-10 22:44:55

user_location_survey where user_id = 51758 → 0건
```

**결과: 운동부위 선택 화면으로 정상 진입한다.** 설문 이력은 없지만 프로 회원권이라 설문 조건이 무너지고 `else if`로 내려간다.

다만 `gym_id`가 다르므로 **body-part 화면 위에 "선택 지점이 출석 지점으로 변경됩니다" Alert이 함께 뜬다.** 여기서 "확인"을 누르면 `setMainGym(테스트 지점)`이 실행되어 앱의 메인 지점이 바뀐다. 이 시점엔 모달이 닫혀 HOC가 언마운트된 상태라 소켓 재연결은 일어나지 않는다.
