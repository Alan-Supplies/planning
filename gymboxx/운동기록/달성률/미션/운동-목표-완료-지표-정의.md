# 운동 목표 완료 지표 정의

> Gymboxx · 초안 v1 · 2026-09-08 · 작성 Austin · 상태: 팀 합의 대기

## 1. 개요

운동 목표는 유저가 정한 기간 동안 운동을 꾸준히 이어갈 수 있도록 돕는 신규 기능이다. 유저는 목표를 만들 때
종료일을 N주 단위로 선택하고, 앱은 그동안의 출석·운동기록을 목표에 귀속시켜 추적한다. 설정한 종료일이
지나도 목표는 자동으로 끝나지 않으며, 유저가 직접 종료를 눌러야 종료된다. 종료 시 결과 화면에서 목표 기간
동안의 활동을 요약해 보여준다.

본 문서는 그 결과 화면에 표시할 지표를 정의한다. 각 지표의 산식, 소스 테이블, 표시 단위, 그리고 논의를
거쳐 확정된 결정 사항을 기록한다. 서버 구현과 클라이언트 표시의 기준이 된다.

### 용어

| 용어 | 정의 |
| --- | --- |
| 운동 목표 | 유저가 생성하는 목표 객체. 시작 시점, 설정 종료일, 종료 시점, 상태(진행 중 / 종료)를 가진다. |
| 시작 시점 | 유저가 목표를 생성한 시각. |
| 설정 종료일 | 유저가 목표 생성 시 N주 단위로 선택한 날짜. 목표 종료를 자동으로 트리거하지 않는다. 화면 안내·리마인드 용도의 목표치. |
| 종료 시점 | 유저가 종료 버튼을 눌러 목표를 종료한 시각. 설정 종료일보다 이르거나 늦을 수 있다. |
| 목표 기간 | 시작 시점 ~ 종료 시점. 모든 지표의 집계 범위. 설정 종료일과 무관하게 실제 종료한 시각까지다. |

## 2. 공통 규칙

| 항목 | 정의 |
| --- | --- |
| 집계 범위 | 목표 기간 = 시작 시점 ~ 유저가 종료를 누른 시점. `goal.started_at <= t < goal.ended_at`. 설정 종료일은 집계에 쓰지 않는다. |
| 기간 일수 D | `D = DATEDIFF(종료 시점 KST 날짜, 시작 시점 KST 날짜) + 1` — 양끝 포함. 시작 당일 종료하면 `D = 1`, 21일째 종료하면 `D = 21`. |
| 주수 W | `W = MAX(D, 7) / 7` — 1주 하한. 경과가 7일 미만이면 1주로 간주한다. 소수는 유지한다(10일 → 1.43). |
| 시간대 | DB는 UTC. 날짜 단위 집계는 `created_at + 9h`로 KST 변환 후 수행. |
| 세션 유효 조건 | `user_exercise_session.is_deleted = 0` |
| 운동 유효 조건 | `user_exercise_session_history.is_done = 1` — 완료 플래그가 있는 운동만 인정. |
| 추적 부위 | `CHEST`, `BACK`, `SHOULDER`, `ARM`, `LEG`, `CORE` 6개. `CARDIO`, `STRETCHING`은 1·2·3번 집계에서 제외. |
| 반올림 | half-up (`Math.round`). 표시 단위는 항목별 명시. |
| 짐박스 평균 | 같은 기간에 출석 1회 이상인 전체 유저를 대상으로, 유저별로 동일 산식으로 계산한 값의 평균. 실시간 계산하지 않고 일배치로 캐시. |

## 3. 항목별 정의

| # | 항목 | 표시 |
| --- | --- | --- |
| 1 | 가장 많이 단련한 부위 | 부위명 |

| 3 | 가장 많이 단련된 근육 | 근육명 |
| 4 | 총 출석 일수 | 일 |
| 5 | 주당 평균 출석 일수 | 소수 1자리, 짐박스 평균과 병기 |
| 6 | 주당 평균 운동시간 | 분, 소수 1자리, 외부 자료와 병기 |
| 7 | 달성률 | % |
| 8 | 총 볼륨 | kg, 정수 |
| 9 | 총 세트수 | 세트, 정수 |
| 10 | 총 운동시간 | 분, 정수 |

### 1. 가장 많이 단련한 부위

- **소스**: `user_exercise_session_history` → `exercise_body_part` → `body_part`
- **산식**: 추적 6부위별 완료 운동 수 `COUNT`. 최다 1개.
- **표시**: 부위명
- **결정 사항**: 단위는 운동 수. 운동이 여러 부위에 매핑되면 각 부위에 1씩 카운트. 동점은 `body_part.id`
  오름차순 1개.

### 2. 가장 조금 단련한 부위

- **소스**: 1번과 동일. `body_part` 6개와 `LEFT JOIN`
- **산식**: 추적 6부위별 `COUNT` 최소. 0회 포함.
- **표시**: 부위명 (복수 가능)
- **결정 사항**: 추적 6부위만 대상. 0개 동률이면 해당 부위 전부 노출.

### 3. 가장 많이 단련된 근육

- **소스**: `user_exercise_session_history` → `exercise_body_part_detail`(`load_ratio`) →
  `body_part_detail`. 세트 수는 `user_exercise_set_history` `COUNT`
- **산식**: 세부 근육별 `SUM(load_ratio × 세트 수)` 최대 1개.
- **표시**: 근육명
- **결정 사항**: 가중합. 무게는 제외하고 세트 수만 반영. 근육별 가용 무게 한도 차이(예: 하체 vs 팔)로
  왜곡되는 것을 피하기 위함.

### 4. 총 출석 일수

- **소스**: `access_history`
- **산식**:
  ```sql
  COUNT(DISTINCT DATE(created_at + 9h))
  WHERE type IN ('ACCESS','REVISIT')
  ```
- **표시**: 일
- **결정 사항**: 출석(게이트 입장) 기준. `REENTER` 제외, `REVISIT` 인정.

### 5. 주당 평균 출석 일수

- **소스**: 4번, 공통 규칙 W
- **산식**: `ROUND(출석일수 / W, 1)`
- **표시**: 소수 1자리, 짐박스 평균과 병기
- **결정 사항**: 소수 1자리. 분모 `W = MAX(D,7)/7` 하한 적용으로 폴백 없이 항상 계산. 분자는 방문 횟수가
  아닌 출석 일수(같은 날 중복 입장 방지).

### 6. 주당 평균 운동시간

- **소스**: 10번, 공통 규칙 W
- **산식**: `ROUND(총 운동시간(분) / W, 1)`
- **표시**: 분, 소수 1자리, 외부 자료와 병기
- **결정 사항**: 소수 1자리. 분모 하한 동일 적용. 외부 비교 자료 출처는 확정 필요.

### 7. 달성률

- **소스**: 목표 달성률 테이블
- **산식**: 기존 달성률 산식
- **표시**: %
- **결정 사항**: Alan과 함께 확인. 목표 달성률 테이블 참조.

### 8. 총 볼륨

- **소스**: `user_exercise_set_history`(`weight`, `count`)
- **산식**: `ROUND(SUM(weight × count))`
- **표시**: kg, 정수
- **결정 사항**: `weight` NULL(맨몸 운동) 제외. DB의 `weight`는 전부 kg 저장이므로 `weight_type` 기준
  lb 변환은 하지 않음.

### 9. 총 세트수

- **소스**: `user_exercise_set_history`
- **산식**: `COUNT(*)`, 부모 history `is_done = 1`만
- **표시**: 세트, 정수
- **결정 사항**: 운동 단위 플래그(`is_done`)로 필터. 세트 단위 완료 플래그는 없음.

### 10. 총 운동시간

- **소스**: `user_exercise_session.started_at`, `end_at`
- **산식**: `ROUND(SUM(end_at − started_at) / 60)`
- **표시**: 분, 정수
- **결정 사항**: `end_at` NULL 세션 제외.

### ~~11. 최대 연속 출석 주~~

- **결정 사항**: 삭제. 목표의 "주" 개념과 현실의 N주차가 달라 혼란 여지가 있음.

## 4. 주당 평균 산식 상세 (5·6번)

```text
D = DATEDIFF(종료 시점 날짜, 시작 날짜) + 1   -- 시작 ~ 유저 종료까지 일수 (KST, 양끝 포함)
W = MAX(D, 7) / 7                          -- 1주 하한

주당 평균 출석 일수 = ROUND(출석일수 / W, 1)
주당 평균 운동시간 = ROUND(운동시간(분) / W, 1)
```

### 예시 — 수요일 시작, 설정 종료일 3주 후

| 상황 | D | W | 출석 일수 | 결과 |
| --- | --- | --- | --- | --- |
| 첫날 1회 출석 후 당일 종료 | 1 | 1.00 | 1 | 1.0 |
| 첫날 0회, 당일 종료 | 1 | 1.00 | 0 | 0.0 |
| 10일째 종료, 4회 출석 | 10 | 1.43 | 4 | 2.8 |
| 설정 종료일(21일째)에 종료, 9회 출석 | 21 | 3.00 | 9 | 3.0 |
| 설정 종료일 지나 30일째 종료, 9회 출석 | 30 | 4.29 | 9 | 2.1 |

### 산식의 성질

- **상한이 자연스럽게 7.0.** 출석일수 ≤ D ≤ 7W 이므로 첫날 1회가 "주 7회"로 부풀려지지 않는다.
- **0회도 0.0으로 표시.** 분모가 0이 되는 경우가 없어 폴백(계산 불가 처리)이 필요 없다.
- **분모는 설정 종료일이 아닌 실제 종료 시점 기준.** 설정한 3주를 분모로 쓰면 첫날 1회 후 종료가 0.3이
  되는데, 목표를 일찍 달성해 종료한 유저도 같이 불리해진다. 실제 경과로 하면 "활동한 기간 동안 주당
  얼마나"라는 의미가 유지된다.
- **종료를 늦게 누르면 희석된다.** 설정 종료일이 지나도 종료하지 않으면 D가 계속 커져 주당 평균이
  낮아진다(예시 마지막 행). 이는 산식이 아니라 종료 UX(설정 종료일 도달 시 종료 유도)로 다룰 문제다.
- **짐박스 평균도 같은 산식.** 대상 유저별로 각자의 D를 써서 개별 주당 값을 구한 뒤 평균낸다.

> **채택하지 않은 대안 — 하한 3일.** D가 1~6일일 때 과소평가되는 문제(3일 3회 출석 → 3.0이지만 실제로는
> 매일 출석)를 보정하려면 하한을 낮출 수 있다. 그러나 `MAX(D, 3)`으로 하면 2일 2회가 4.7로 뛰어 반대로
> 과대평가된다. 짧은 기간의 과소평가가 과대평가보다 사용자 불만이 적다고 판단하여 하한 7일을 채택한다.

## 5. 테이블 참조

| 테이블 | 사용 컬럼 | 비고 |
| --- | --- | --- |
| `user_exercise_session` | `id`, `user_id`, `started_at`, `end_at`, `is_deleted`, `created_at` | 운동기록 1건 = 1행 |
| `user_exercise_session_history` | `id`, `user_exercise_session_id`, `exercise_id`, `is_done` | 세션 내 운동 1개 = 1행 (라운드별) |
| `user_exercise_set_history` | `user_exercise_session_history_id`, `set_number`, `count`, `weight` | 세트 1개 = 1행. `weight`는 kg |
| `exercise_body_part` | `exercise_id`, `body_part_id`, `status` | 운동 → 부위 (1:N) |
| `exercise_body_part_detail` | `exercise_id`, `body_part_detail_id`, `load_ratio`, `status` | 운동 → 세부 근육 + 가중치 |
| `body_part` | `id`, `part`, `status` | 8종, 추적은 6종 |
| `body_part_detail` | `id`, `body_part_id`, `detail_part`, `status` | 세부 근육 → 부위 |
| `access_history` | `user_id`, `type`, `created_at` | `type`: `ACCESS` / `REVISIT` / `REENTER` … |

## 6. 남은 확인 사항

- **6번 외부 비교 자료 출처** — WHO 주 150분 중강도 권고 등 후보. 표기 문구와 함께 확정 필요.
- **1번 동점 처리** — 현재 `id` 오름차순 1개. 2번처럼 전부 노출할지 결정.
- **10번 이상치 상한** — 6시간 초과 세션 등 종료 누락 의심 데이터를 제외 또는 cap 할지.
- **7번 달성률 산식** — Alan 확인 후 본 문서에 산식 원문 첨부.
- **설정 종료일 이후 종료 유도** — 설정 종료일 도달 시 푸시·배너로 종료를 유도할지, 일정 기간 방치 시 자동
  종료할지. 방치 기간이 길어질수록 5·6번이 희석되므로 정책 필요.
