## 1. 범위와 읽는 기준

사용자 행동과 검증 가능한 결과를 먼저 정의한다. `user_goal`, `user_mission`, `user_goal_attendance_time`은 **60% 확정된 잠정 테이블명**이며 컬럼명·타입·DDL은 재검토 대상이다. 아래의 식별자는 의미를 설명하기 위한 이름이지 DB 확정안이 아니다.

- **기존**: 로컬 기획에서 일관되게 확인한 요구사항.
- **보완안**: 빈칸·충돌을 해결하기 위해 이번에 채택한 구현 검토안. PO 확정으로 간주하지 않는다.
- **선행 결정**: 기준 데이터나 제품 판단이 필요해 해당 기능 개방 전에 해결해야 할 항목.

참조: [목표 문구](운동목표문구.md), [생성 규칙](미션생성시스템.md), [계산 규칙](미션달성률계산시스템.md), [기존 논의](미션생선시스템_주의.md), [설계 컨텍스트](../목표및미션시스템설계.md), [완료 지표](운동-목표-완료-지표-정의.md).
외부 Linear 최신본을 검증한 문서가 아니라 위 로컬 자료와 아래 worktree 및 운영 DB 읽기 전용 조회를 대조한 결과다. 원문 전사본은 보존하고 충돌 해석은 이 문서에 기록한다.

### 운영 DB 대조 결과 (2026-09-09)

사용자가 제공한 연결로 READ ONLY 트랜잭션에서 information_schema·소규모 운동 마스터·최근 ID순 1,000건의 집계만 조회했다. 쿼리 실행 제한은 5초였고 데이터 변경은 하지 않았다. 접속 자격 증명과 회원별 기록은 문서에 저장하지 않는다. 아래 표본 수치는 전체 데이터 비율로 일반화하지 않는다.

| 확인 사실 | 요구사항에 반영할 내용 |
|---|---|
| user_goal/user_mission/user_goal_attendance_time 및 mission/goal 기준량 테이블은 조회 시점에 없음 | 신규 스키마이며 존재하는 것으로 전제하지 않는다. |
| exercise_body_part_detail에는 load_ratio만 있고 contribution 없음; exercise에 유산소 강도 컬럼 없음 | 직접 1.0/보조 0.5는 선행 데이터 필요. 강도 컬럼은 이번 구현의 선행 조건에서 제외한다. |
| exercise에 training_type, unit, has_weight, weight_role(LOAD/ASSIST)이 있음 | 신규 컬럼으로 중복 신설하기 전에 기존 의미를 검토. ASSIST 중량을 부하로 더하지 않기. |
| 활성 성격 매핑은 CARDIO 13종, STRETCHING 7종이며 training_type과 일치 | 이 결과는 기존 CARDIO 라벨 13종의 일치만 확인한 것으로 분류 정확성이나 누락 부재를 입증하지 않는다. 사용자 확인상 현재 분류가 부정확하다. 유산소 정본은 training_type으로 변경하며 전체 활성 운동 분류를 검수한다. |
| 활성 CARDIO 중 unit=MINUTE 11종/SET 2종; STRETCHING은 MINUTE 6종/SET 1종; MUSCLE에도 MINUTE 6종 | 성격만 보고 count를 시간으로 해석하지 않는다. 시간 종목이라고 unit 문자열만 보고 count에 60을 곱하지 않는다. |
| 세트에 duration_second, done_at 존재. 최근 1,000건은 둘 다 비NULL 0건 | 컬럼 존재와 쓰기 완료는 다르다. R37 시간 원천 전환과 레거시 단위 검증 필요. 세트 done_at 필수 필터를 넣으면 기존 기록이 전부 누락될 수 있다. |
| 최근 세션 1,000건 중 started_at NULL 89건, end_at 비NULL 634건 | NULL 시작 시각은 실제 존재. 두 조건의 교집합은 미조회이며 종료 세션 누락률로 해석하지 않는다. R19 적용 전에 종료+시작누락 분포 확인과 보정 정책 검토. |
| access_history_id NOT NULL, source 컬럼 없음(gym_id는 nullable) | 외부 운동 원천 연결 변경 필요. source='OUTSIDE' 필터를 현재 테이블에 바로 적용할 수 없다. |
| exercise_effect와 is_primary는 존재 | 효과축 테이블 자체 부재가 아니라 균형 데이터 검수·구성 충돌이 남은 문제다. |
| 세트 weight는 decimal(10,7), 시각은 timestamp/datetime(소수 초 미지정) | kg 의미는 worktree 쓰기 코드로 확인한 것이며 전체 과거 데이터 단위를 입증한 것은 아니다. 실제 DB 경계 테스트는 초 정밀도로 수행한다. |

## 2. 용어와 불변 조건

| ID | 구분 | 요구사항 |
|---|---|---|
| R01 | 기존 | 목표는 사용자가 원하는 결과 문구, 미션은 그 목표를 위한 운동 행동과 총량이다. 슬롯은 미션을 담는 고정 자리이며 교체 전후에도 번호가 유지된다. |
| R02 | 기존 | 회원당 활성 목표는 **최대 1개**다. 생성 전·완료 후에는 0개일 수 있다. 목표의 현재 미션은 1~5개이며 정상 구성 개수는 목적별 규칙을 따른다. |
| R03 | 기존 | 미션 1개 = 게이지 1개. 목표 전체 달성률·미션 평균·합산 달성률을 만들지 않는다. 주간 초기화·기간 비례·300% 캡도 없다. |
| R04 | 기존 | 완료는 사용자의 명시적 확정으로만 수행한다. 미션 0%에서도 완료 가능하고 전부 100%여도 자동 완료·자동 교체하지 않는다. 불러오기·완료 취소·재활성은 제공하지 않는다. |

## 3. 목표 생성·변경·일정

| ID | 구분 | 요구사항 |
|---|---|---|
| R05 | 기존 | 세그먼트별 목적 5종 문구를 마스터에서 조회한다. 다이어트→근력→건강→체력→자세 순서다. 무료 회원은 결제 완료 이후 설정할 수 있고 유료 회원은 홈·마이페이지에서 진입한다. 서버도 설정 권한을 검증한다. |
| R06 | 기존+보완안 | 객관식은 유효한 문구 ID를 받아 서버가 문구와 목적을 결정·복사한다. 클라이언트가 보낸 목적·문구로 마스터 의미를 덮어쓰지 못한다. 직접 입력은 문구 ID 없이 입력 문구와 분류된 목적을 보존한다. 마스터 변경은 기존 목표에 소급하지 않는다. |
| R07 | 보완안 | 문구는 trim 후 1~200자, 이유는 trim 후 0~500자(선택, 미입력은 빈 문자열)로 정규화한다. 길이는 Unicode 코드 포인트 기준이며 마스터 문구도 같은 제한을 검증한다. 기타 문구의 목적은 버전 있는 키워드 규칙으로 분류하고, 복수 목적 충돌·매칭 없음은 임의 분류하지 않고 생성 실패로 반환한다. 키워드 목록이 확정되기 전에는 기타 생성 진입을 개방하지 않는다. |
| R08 | 보완안 | 생년·성별은 회원 정보에서 확보한다. 연령대는 KST 생성 연도−출생 연도 기준 10~29/30~39/40~49/50세 이상을 사용한다(생년만 있는 회원 기준). 누락·미지원 값·10세 미만은 임의로 남성/30대로 대입하지 않고 지원 불가로 반환한다. 목표 생애 동안 생성 세그먼트와 규칙 버전을 고정하고 교체 분모는 그 세그먼트의 최신 승인 기준량으로 계산한다. |
| R09 | 기존+보완안 | 설정 종료일은 KST 날짜이며 선택 사항이다. 입력 시 생성일 이전은 거부한다. 지난 종료일은 목표·미션을 자동 종료하지 않는다. N주 선택 UI가 보내는 날짜를 사용하며 허용 N주 목록은 화면 계약에서 확정한다. |
| R10 | 기존+보완안 | 운동 예정 일정은 KST 요일별 최대 한 시각, 0~7개다. 요일 중복·잘못된 시각(24:00 포함)은 거부한다. 일정 변경은 활성 목표에서 전체 목록 교체로 처리하고 빈 목록은 전체 해제다. 예정일 불참·추가 방문·일정 변경은 미션 분모·분자에 영향이 없다. 리마인드 실제 발송은 별도 범위다. |
| R11 | 보완안 | 목표 생성은 목표·초기 미션·일정을 하나의 원자적 작업으로 저장한다. 생성 실패 시 일부 목표나 빈 슬롯을 남기지 않는다. 활성 목표가 있는 일반 생성은 충돌이고, 명시적 목표 변경만 기존 종료+새 목표 생성을 함께 수행한다. 새 목표 생성 실패 시 기존 목표를 유지한다. |

| R17 | 선행 결정+보완안 | 1차 계산 타입은 scheme의 4종이다. 효과 세션·출석 폴백은 개방하지 않는다(효과 테이블 자체는 운영 DB에 존재). 원문의 65세 이상 균형 필수는 모든 목적에 적용되나 5슬롯 제한·효과축 배타성과 충돌한다. 구성 재합의 전에는 해당 세그먼트의 신규 생성을 개방하지 않는다. 이는 PO 확정 제외 정책이 아니라 불완전한 구성을 성공으로 반환하지 않기 위한 임시안이다. |
| R18 | 보완안 | 입력·기준량·매핑 누락 또는 구성 검증 실패 시 오류 코드와 실패 단계/규칙 버전을 남기고 저장을 롤백한다. 임의의 출석형 폴백이나 분모 1을 넣지 않는다. 원문 폴백은 출입/기록 기준부터 충돌하므로 승인된 폴백 데이터가 생기기 전에는 적용하지 않는다. |

## 5. 실적 집계 계약

| ID | 구분 | 요구사항 |
|---|---|---|
| R19 | 보완안 | 실적 귀속 시각 t는 **세션 started_at**으로 통일한다. 생성·수정 API 호출 시각이나 출석 created_at을 대신 쓰지 않는다. `assignedAt <= t < cutoff`인 종료 세션을 집계한다. cutoff는 해당 재계산의 서버 시각, 교체/종료 때는 그 조작의 확정 시각이다. started_at 누락·end_at < started_at·cutoff 뒤에 종료된 세션은 제외하고 원천 오류를 계측한다. 부여 전에 시작하여 이후 종료한 세션은 새 미션에 포함하지 않는다. 세트별 시각이 없으므로 세션을 시간 비례 분할하지 않는다. |

### 시간 기록 호환 계약

**R37 · 운영 DB 반영 보완안**: 시간 실적의 정본은 `duration_second`(초)로 정한다. 값이 있으면 이것만 사용하며 count를 더하지 않는다. NULL인 레거시 기록은 시간 측정 종목이며 구버전 입력이 초였음이 검증된 경우에만 count를 초로 해석한다. DTO에는 ‘횟수 or 초’라고 적혀 있지만 운영 unit은 MINUTE이므로 과거 클라이언트·백필 검증을 생략하지 않는다. 단위를 입증하지 못한 기록은 제외·계측하며 시간 미션을 준비 완료로 선언하지 않는다. 0초는 0, 음수·비유한 값은 입력 거부다. 시간 쓰기 경로·기존 기록 정규화·라이브러리 버전 정합을 함께 완료해야 한다.

### 유산소 분류 정비

**R38 · 사용자 문제 제기 반영**: 유산소 판정의 정본은 `exercise.training_type`이다. 현재 분류를 정확하다고 가정하지 않는다. 기존 CARDIO 13종만 확인하면 유산소로 잘못 포함된 운동만 찾고 누락된 운동을 놓칠 수 있으므로 **전체 활성 운동**을 대상으로 검수한다.

- 정비 목록에는 운동 ID·명칭·현재 training_type·변경 제안·근거·검수 상태를 기록한다. 기존 부위 CARDIO 라벨, equipment_type, unit, 운동 설명은 후보를 찾는 보조 자료이며 자동 확정 기준이 아니다.
- 오탐(유산소가 아닌데 CARDIO), 누락(유산소인데 MUSCLE/STRETCHING/NULL), 시간 기록 가능 여부를 각각 확인한다. 특정 운동의 최종 분류는 운영 담당자/트레이너 검수로 확정한다. 이 문서 작성에서는 운영 데이터를 수정하지 않았다.
- `unit=MINUTE`만으로 CARDIO로 바꾸지 않는다. 운영 DB에는 시간 측정 근력·스트레칭도 있다. CARDIO이지만 SET인 운동은 시간 기록 지원 정비 전 횟수를 분으로 계산하지 않는다.
- 반영 전후 변경 ID·분류별 개수·불일치 목록을 대조한다. 승인한 비유산소/유산소 대표 종목과 누락 사례로 집계 포함·제외를 검증한다. 현재 데이터 분포와 정답 분류 검수는 별도 증거다.
- 분류 변경 시 진행 중 미션은 R26에 따라 재집계하며 실적이 오르거나 내려갈 수 있다. 기존 완료/교체 이력은 R29대로 보존한다. 분모는 분류 정비로 자동 변경하지 않는다.

2026-09-09 변경: 이전 기획의 ANY/MODERATE/VIGOROUS와 고강도×2는 이번 구현에서 폐기한다. 스트레칭 판정 변경은 이번 지시에 포함되지 않으므로 R24를 유지한다. 생성/계산 원문 전사본의 강도 설명은 과거 기획이며 이번 요구사항 R23이 우선한다.

| 삭제 | R31 soft delete | 삭제 표시 컬럼과 조회 공통 필터 결정 |
| 귀속 시각·이력 | R19 started_at, R29 종료 스냅샷 | 세션 경계 정책 제품 검토; 기존 완료 지표의 범위와 혼용 금지 |
| 유산소 판정 | 사용자 방향: training_type=CARDIO, 실제 분 합산, 강도 미사용 | R38 전체 활성 운동 오분류·누락 검수, 실제 분 기준량 확인. 체력 4슬롯은 보완안으로 제품 검토 |
| 65세 이상·폴백 | R17/R18 구성 확정 전 생성 불가 | 5슬롯 배분, 균형 주효과 데이터, 축 교집합, 출석 원천 확정 |
| 직접 입력·회원정보 누락 | R07/R08 명시적 실패 | 키워드 사전 및 미지원 세그먼트 정책 승인 |
| 분자 데이터 | 기여도/training_type/측정 타입 기반 | 기여도 확보·유산소 분류 정비·시간 호환 검증 후 알려진 세트로 검증. 누락 분류를 유산소로 임의 대입하지 않기 |
| 분모 데이터 | 공식은 유지, 수치는 승인된 기준표만 | 8세그먼트 기준량·스트레칭 부위별/볼륨 기준량 검수. 기존 환산분 분모를 실제 분으로 이름만 바꾸지 않기 |
| 외부 운동 | 계산에서는 포함 | 현재 출석 필수 생성 경로와 분리하는 원천 지원 작업 확인 |
| 초과 표시 | 서버 숫자 캡 없음 | 게이지 100% 초과 표현과 99.6% 표시/버튼 차이는 앱 검수 |

위 선행 조건이 해결되지 않은 목적/세그먼트는 선택 목록에서도 준비되지 않은 상태를 알려야 한다. 사용자에게 지원 가능한 것처럼 노출한 뒤 이유 없이 실패시키지 않는다. 지원 범위를 줄여 출시할지는 별도 제품 결정이며, 이 문서는 전체 요구사항이 완료되었다고 판정하지 않는다.

## 8. 컬럼 재검토 입력과 구현 순서

필요한 **정보**부터 검토한다. 컬럼을 추가하는 것만으로 아래 요구사항이 해결되지는 않는다.

- 목표: 문구/목적 스냅샷, 생성 세그먼트, 생성·로테이션 규칙 버전(또는 목록 스냅샷), 종료 시각, 삭제 표시.
- 미션: 슬롯·회차 식별, 분모 스냅샷·단위, 현재 분자/비율, 최초 도달/종료 시각, 마지막 계산 시각(진단용). 중복 상태를 저장하면 동시 갱신 규칙을 갖춘다.
- 일정: 목표+요일 유일성, KST 시각. 회원의 실제 출석 원장과 구분한다.
- 제약: 회원당 활성 목표 최대 1, 목표·슬롯당 현재 미션 최대 1, 목표·슬롯·회차 유일, 부모 소유권 일치. MySQL에서 가능한 유일 제약과 회원 락을 함께 설계하며 PostgreSQL 부분 인덱스 예제를 그대로 복사하지 않는다.
- 소수 타입/정밀도: 기여도와 초→분 소수를 보존하고 표시 반올림과 교체 판정을 분리할 수 있어야 한다. rate를 저장할지 파생할지는 검토하되 numerator와 불일치를 허용하지 않는다.

순서: (1) 선행 데이터·지원 구성 확정 → (2) 요구사항별 순수 생성/계산 테스트 → (3) 컬럼·제약 및 원천 변경 트랜잭션 설계 → (4) 목표·미션 API/기록 재계산 연결 → (5) 실제 MySQL 경합·롤백 검증 → (6) 앱 시나리오 검수. 구체적인 케이스와 완료 조건은 [테스트 목록](테스트목록.md)을 따른다.
