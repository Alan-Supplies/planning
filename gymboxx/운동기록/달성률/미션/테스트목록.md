# 운동 목표·미션 테스트 목록

작성: 2026-09-09 · 기준: [요구사항](specification.md) · 상태: **목록 작성 완료, 테스트 코드 작성·실행 전**

보완안의 기대값은 제품 확정값이 아니다. 보완안이 바뀌면 연결된 케이스도 함께 갱신한다. P0는 지원 범위 개방 전 필수, P1은 표시·조회·운영 검수다. 미지원 기능은 성공 케이스를 통과했다고 표시하지 않고 ‘개방 차단 검증’과 ‘선행 조건 해결 후 성공 검증’을 나눈다.

## 1. 공통 픽스처

실제 회원·운영 DB 대신 고정 데이터를 사용한다. 연령/성별 수치는 생성 기획의 예시이며 스포츠 과학적 유효성을 테스트하는 값은 아니다.

- 회원 A/B, KST 기준 고정 시계, 목표 시작과 최초 미션 부여 `2026-09-09T00:00:00Z`(09:00 KST), 재계산 시각 `03:00:00Z`(12:00 KST).
- A의 가슴 미션 M1: 분모 40, 코어 M2: 40, 유산소 M3: 360, 전신 스트레칭 M4: 90. 계산용으로 직접 만든 4슬롯이며 목적별 생성 테스트의 35세트분과 혼용하지 않는다.
- 유효 세션: A 소유, started_at=01:00Z, end_at=02:00Z, 비삭제, 운동 is_done=1, 활성 운동/매핑.
- 가슴 운동 C1: 중간가슴 직접 1.0, C2: 윗가슴 직접 1.0+중간가슴 보조 0.5+팔 보조 0.5. 볼륨 중복 검증 C3: 가슴 서로 다른 세부부위 직접 매핑 2개.
- 시간 종목: training_type=CARDIO인 운동 2종, 가슴/어깨 스트레칭, MOBILITY이지만 스트레칭이 아닌 근력 종목. `count`의 초/횟수를 판별할 측정 타입을 함께 설정한다.
- 매 케이스는 새 상태에서 시작한다. 정밀 소수 비교는 선택한 저장 정밀도로 검증하고 표시 반올림은 별도 검증한다. 기대값은 생성/집계 구현 함수를 재사용해 계산하지 않는다.

실행 시 기록할 항목: 테스트 ID, 실행 일시, 서버/라이브러리 커밋, 규칙·기준 데이터 버전, 결과(PASS/FAIL/BLOCKED), 증거(테스트 출력 또는 화면), 실패 후속 작업. 현재 위 모든 케이스는 **NOT RUN**이다.

완료 조건:

1. 개방할 목적/세그먼트의 선행 결정 및 기준 데이터를 확정하고 해당 성공 경로를 실행한다. 미지원 거부만 통과한 상태를 전체 미션 기능 완료로 판정하지 않는다.
2. 그 범위의 모든 P0 및 P1 검수를 통과하고 실패·BLOCKED를 해소한다.
3. 실제 MySQL에서 경합·롤백·유일성 검증을 통과하고, 서버가 성공 응답한 기록과 홈 저장값의 정합성을 확인한다.
4. 숫자·단위·교체 권한·이력 의미를 앱에서 검수한다. 문서만 변경한 이번 작업에서는 서버 테스트를 실행하지 않았다.
