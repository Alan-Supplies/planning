# 07. 부위 매핑 중복 방지 제약 추가 · 대리키 전환

> [전체 목차](README.md) · [통합 원문](../DB_구조_업그레이드_방안.md)

같은 조합의 중복을 막으면서 정정 이력 보존을 가능하게 하는 작업

## 무엇을 바꾸는가

`exercise_body_part` 에 부분 고유 제약 추가 — 현재 고유 제약이 전혀 없음 `exercise_body_part_detail` 은 자연키 복합 기본키를 대리키로 전환

## 무엇을 막고 무엇을 허용하는가

여러 부위 등록은 그대로 허용됨 · 제약이 막는 것은 같은 조합의 중복

|상태|판정|
|---|---|
|(데드리프트,등) · (데드리프트,하체)2행|✅ 정상이고 필요—부위 개수 제한 아님|
|(데드리프트,등)이 두 번 등록|❌ 차단 대상—부위 집계가 2배로 계상|
|사용 중(데드리프트,등)1행 + 비활성 이력 여러 행|✅ 허용—정정 이력 보존|

## 어떻게 바꾸는가

1. 생성 열 추가 후 `UNIQUE(exercise_id, body_part_id,` 생성열 `)` — 사용 중 1행만 허용하고 비활성 이력은 제한 없음

2. `exercise_body_part_detail` 에 대리키 추가 후 기본키 이관 · 동일한 부분 고유 제약 적용

3. 기본키 해제 시 외래키 지지 인덱스를 같은 명령에서 교체 — 누락하면 실행 오류

## 무엇이 좋아지는가

부위 집계의 이중 계상 위험 제거 — 같은 조합이 2행이면 부위별 운동량 목표의 분자가 2배가 됨 · 현재는 집계 쿼리마다 중복 제거를 강제해야 하고 한 곳이 빠지면 조용히 틀린 값이 나옴

정정 이력 보존이 물리적으로 가능해짐 — 현재 세부부위 매핑은 자연키 복합 기본키라 같은 조합을 비활성 처리한 뒤 다시 넣는 것이 불가능 · 분류 정정을 반 복하려면 기존 행을 덮어써야 하고 그러면 이전 값이 사라짐

## 주의

현재 중복은 0건 — 예방 목적이며 우선순위는 후속 · 위험은 비활성 90행을 되살리는 정정 작업에서 발생(같은 조합을 새로 넣으면 2행)
