이번 논의로 종전 안 대신 선택한 지점과 그 근거

|항목|종전 안|선택안|근거|
|---|---|---|---|
|성격 태그의 축 분리 방<br>식|한 테이블 유지 + 효과 축 화이트리스트를 문서에 기록|효과 축 테이블과 추천용 태그 테이<br>블로 분리|계산 조건을 사람이 기억하는 구조가 사라지고 DB 제약으로 막힘<br>·<br>`is_primary`가 의미 있는 행에만 존재|
|컬럼 분리 + 값 없음 방<br>식|검토 대상|채택하지 않음|기본키에 빈 값을 넣을 수 없어 대리키 전환 필요·고유 제약이 빈<br>값을 서로 다른 값으로 취급해 지금 막히고 있는 중복을 새로 뚫음|
|기여도 임계값|절대 0.5 기준|상대 기준—그 운동 최댓값의 60%<br>이상|절대 기준은 부위를 자세히 등록한 운동일수록 주 부위가 사라짐·<br>상대 기준은 직접 없는 운동 0종|
|장비 12종 값 이름|확정 필요|제안안 그대로 확정|재배치 작업 착수 가능|
|균형 운동 세션 수 목표<br>채택 범위|주 효과만 또는 주 효과 + 부가|주 효과만·신규 균형 종목 4~6종<br>등록 후 개방|부가 포함은 스쿼트·런지를 균형 달성으로 계상·주 효과 적격이 4<br>종뿐이라 종목 확충이 개방의 짝|
|파운드 입력 허용|정책 결정 대기|허용 유지|환산이 1회성 정리가 아니라 상시 경로|
|무게 저장 단위<br>(2026-09-03 확정)|`weight_unit`<br>+<br>`weight_kg`<br>생성 열 신설|**컬럼 신설 취소**·`weight`<br>를 kg 고정으로 확정|저장 정책이 처음부터 kg 이었고 서버 저장 경로와 훈련량 집계에<br>단위 분기가 없음·입력 경로에서 kg 으로 환산한 값만 저장하고 원값(lb)은<br>남기지 않음·`weight_type`<br>은 표시 단위 선호이지 저장값의 단위가 아님|
|세트 강도 척도|여유 반복 수 권고|자각 강도 1~10(세션과 동일 척도)|세션 컬럼에 이미 188,095건(57.4%)축적·세트 평균과 세션 값<br>대조 검증 가능|
|최고 기록 종류 관리 방<br>식<br>(2026-09-03 재변경)|참조 테이블<br>(2026-08-21 선택)|**이력 테이블의**<br>**`record_kind`**<br>**enum·시작 4종**(최고 중량·최고 반복 수·단일 세트 최고 훈련량·최장 지속 시간)|enum 은 참조 테이블이 있어도 사라지지 않음—종류마다 서버 계산이<br>다르므로 분기 키가 코드 상수로 반드시 존재하고, 참조 테이블을 두면<br>`code`<br>와 서버 상수를 다시 대조하게 됨·성립 규칙은<br>`exercise`<br>플래그가 더 잘 담음(AND 조건 가능)·"대량 테이블 열거형 확장<br>비용" 근거는 MySQL 8 에서 성립하지 않음(enum 끝 추가는 INPLACE)|
|최고 기록 종류별 표기<br>명·단위·정렬|참조 테이블 컬럼|서버 상수 + 메타 API<br>(`GET /v1/meta/personal-record-kinds`)|표기명 오타 수정이 앱 심사 없이 배포 한 번으로 끝나고 구버전 앱에도<br>즉시 반영·소비자가 프론트만이 아님(푸시·리포트·어드민·DW)|
|최고 기록 종류별 유효<br>범위|참조 테이블<br>`min_value`/`max_value`|서버 상수·검증 전용·노출 안 함|운영에서 조정할 수요가 아직 없음·필요해지면 그때 참조 테이블을 얹음|
|종목별 측정 방식 선언<br>(2026-09-03 폐기)|`measure_type enum('WEIGHT_REPS','REPS','DURATION')`<br>신설|**폐기**·`exercise`<br>불리언 플래그 3종<br>(`has_weight`(기존)·`has_duration`·`has_reps`)|enum 단일값은 "무게도 있고 시간도 있는" 종목(웨이티드 플랭크)을<br>표현하지 못하고 성립 조건을 AND 로 쓸 수 없음·개발 DB 실측에서<br>`measure_type`<br>은 신설되지 않았고<br>`training_type`·`weight_role`<br>이 다른 축으로 신설됨|
|측정 방식 플래그 접두|`is_repeatable`|`has_reps`|`has_weight`<br>의 직계 형제이고 같은 축·값 보유에<br>`is_`<br>를 쓰는 전례가 이 스키마에 없음(`has_`<br>4건 대<br>`is_`<br>42건이며 후자는 전부 상태·분류)·`is_repeatable`<br>은 "여러 번 할 수 있는"으로 읽혀 모든 운동에 해당|
|세트 저장 방식 전환 범위|전면 전환 또는 신규만|대리키는 전건·수행 시각과 갱신<br>방식은 신규 기록만|과거 시각을 보간하면 추정치가 원천에 실측처럼 들어가 작업 원칙<br>3 위반|
|세트 수행 시각 컬럼명<br>(2026-09-03 확정)|`performed_at`|`done_at`|반영된 스키마가<br>`done_at`<br>이며 계획 문서의 이름과 다름·이 이름을 정본으로 둠|
|감량·회복 태그|열거형에서 폐기|추천용 태그 테이블로 이관해 보존|틀린 값이 아니라 다른 축의 값·추천 근거로 계속 사용|
|태그 테이블 시각 컬럼|달성률 소급 방지·웨어하우스<br>증분 적재|회귀 원인 추적 하나|달성률은 별도 결과 테이블에 확정 저장되어 무관·300행 이하 소<br>테이블이라 증분 적재 불필요|
|순발력(<br>`PLYOMETRIC`)<br>태깅|근력(<br>`STRENGTH`)과 같은 급|값만 먼저 추가·태깅은 후순위|목표 5종 어디에도 미사용·동작 양식 축으로 식별 가능|
|거리 측정|측정 방식 4종에 포함|제외·3종으로 시작|해당 종목 0건·저장 컬럼 없음|
|중복 방지 제약|선행 필수|후속|현재 중복 0건|
|부위 사전 테이블명|즉시 변경|축 컬럼만 먼저·이름은 후속|외래키 5개 + 앱 코드 참조로 코드 배포 동반 필요(2026-08-21 재<br>실측·종전 2개는 오기)·축 컬럼은 부위·성격 혼재를 표시할 뿐 해<br>소하지 않으므로 최종 형태 결정은 [15](15_남은_결정_조사_항목.md)로 이월([02](02_부위_라벨_축_구분.md) 참조·2026-09-01)|
