## 흐름

```text
10/27 회사컴 세션 (할일찾기.md)
  ├─ 기술 과제 추천: 알림 2차 개편, 인증·인가 정비
  └─ 상품 과제로 전환 → 1순위 "방문 리듬 제품" → PO 논의거리 정리
        │
10/29 PO 피드백: "통계 알림·출석 위젯은 부수적. 본질을 고민하라"
  ├─ 본질 후보 A/B/C 정리 → 데이터 전엔 분기 계획으로 잡기 어렵다
  └─ "메이저는 아니지만 할 것 중 하나" → 부수 과제로 분리
        │
DevOps 한 달짜리 탐색 (Linear·Slack·저장소 대조, 주인 있는 영역 제외)
  ├─ 1순위 S3 정리   → "코드 다 고쳐야 해서 100% 의문"
  ├─ 2순위 복구 리허설 → "중요성 공감을 얻기 어렵다"
  └─ 3순위 DB 부하    → "부하가 문제 아니면?" → 실측 CPU 평균 2.1%, 탈락 확정
        │
AWS 실측 (운영 계정, 읽기 전용)
  ├─ 1순위의 코드 수정 범위는 이미지 버킷 수준으로 좁음 → 목표를 "의도치 않은 공개 0"으로 재정의
  └─ 여권 사진 재확인 → 10/1 조치는 새 경로만 막았고 옛 경로 604장 + 트레이너 서류가 지금도 공개
        │
S3 민감 데이터 분리 = 4분기 메인 확정
  └─ supplies-auth 참여 검토 → 본체는 HRIS와 묶여 인수 불가
        → S3 열람 권한 판정에서 이어지는 "HQ 직원 인증 수렴"을 1분기 후보로
```

## 부수 과제 KPI

- **본질 탐색**: 결과물 기준으로 잡는다 — 1주 차 검증 분석으로 본질 결정(A 갈 이유 없음 / B 효과 못 느낌 /
  C 혼자라 끊김), 최소 실험 1회와 홀드아웃, 분기 안에 잴 선행 지표(첫 6주 주 2회 이상 비율, 기준선 45%)
- **숫자 재검증**: 완료 여부만 — 쿼리 `.sql` 저장, 정의 명시, 당시 값과 비교
