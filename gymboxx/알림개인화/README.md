# 알림 시스템 개편 · 개인화

작성: 2026-10-07
상태: 조사·초안. 구현 결정 전이다.

우선순위: **1순위** (2026-10-08 사용자 결정). [개편 착수 계획](00_개편_착수계획.md)에 관련 스레드, 이번 논의 범위와 다음 행동을 기록한다.

관련 자료: [Slack 논의 스레드](https://w1622455415-twy380170.slack.com/archives/C0AQJU4QMEG/p1789889756121859), [Linear 프로젝트: 푸시 알림 시스템 업데이트](https://linear.app/suppliesfitness/project/푸시-알림-시스템-업데이트-50d91425ccf4).

10/7 첨부 기획의 최신 요구는 **공지 및 이용 안내사항·편의사항·마케팅 정보 수신 동의** 3종과 각각의 상세보기다. 운동 공유 리마인드는 **종료 후 30분·재발송 간격 15일·공유 클릭 이력 0회** 조건이다. 기존 설계안의 카테고리·데이터 모델과 다른 부분은 [착수 계획의 차이표](00_개편_착수계획.md#기존-초안과-대조할-차이)에서 먼저 확인한다.

회원이 알림을 카테고리별로 켜고 끄고, 받지 않을 시간대를 정할 수 있게 한다. 이를 위해 지금 user 모듈과 여러 발송처에 흩어진 알림 규칙을 하나의 도메인으로 모은다.

## 현황에서 먼저 볼 것

- 앱 설정 토글은 "푸시 알림"과 "마케팅" 2개다. 그런데 서버의 발송 경로 대부분이 이 동의를 검사하지 않는다.
- 푸시를 실제로 보내는 SQS `app_push` 컨슈머 코드를 찾지 못했다. 이 컨슈머가 판정 지점 후보라서, 위치 확인이 첫 작업이다.
- 발송 이력이 없다. 중복 방지는 배치마다 다르게 하고, 아예 없는 배치도 있다.

## 결정할 것

1. 카테고리 구성: `서비스 알림`·`커뮤니티` 를 따로 둘지. `회원 활동`(가칭)의 정식 이름
2. 서비스 알림을 끌 수 있게 할지
3. 수신 시간대 동작: 버림 / 끝나면 발송 / 카테고리별
4. 광고 야간 동의를 받을지
5. 도메인 분리 수준: app-server 모듈(A) / 디스패처(B) / 외부 도구(C). 초안은 B 를 제안한다
6. 기존 회원의 새 카테고리 기본값
7. 발송 이력 보존 기간과 기록할 지표
